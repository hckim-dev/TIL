Big Endian(빅 엔디안)과 Little Endian(리틀 엔디안)은 컴퓨터 메모리에 다바이트(Multi-byte) 데이터를 저장할 때 바이트를 배열하는 순서(Byte Order)의 차이입니다.

예를 들어, 4바이트짜리 16진수 데이터 `0x12345678`이 있다고 가정해 보겠습니다.

(상위 바이트: `12`, 하위 바이트: `78`)

<a id="notion-36f1d46c18fc807fababd2e56fc7831a"></a>

### 1\. Big Endian (빅 엔디안)

- **개념:** 사람이 숫자를 쓰는 방식 그대로, 상위 바이트(MSB)부터 메모리의 낮은 주소에 차례대로 저장합니다.
- **저장 방식 (낮은 주소 → 높은 주소):**

  `12` → `34` → `56` → `78`
- **특징:**

  - 메모리를 디버깅할 때 사람이 읽기 직관적이고 편합니다.
  - 주로 네트워크 전송(Network Byte Order)이나 대형 컴퓨터(Mainframe)에서 사용됩니다.

<a id="notion-36f1d46c18fc80d9a4def9d02237fbdd"></a>

### 2\. Little Endian (리틀 엔디안)

- **개념:** 거꾸로 하위 바이트(LSB)부터 메모리의 낮은 주소에 차례대로 저장합니다.
- **저장 방식 (높은 주소 → 낮은 주소):**

  `78` → `56` → `34` → `12`
- **특징:**

  - 상위 바이트가 뒤에 오기 때문에 하위 바이트만 떼어서 연산할 때 속도가 빨라 CPU 연산에 효율적입니다.
  - 우리가 흔히 쓰는 **Intel, AMD, ARM(기본값) 등의 일반적인 CPU(x86, x64)** 아키텍처에서 표준으로 사용합니다.

<a id="notion-36f1d46c18fc807089accecfc729eed5"></a>

### 요약 표

|  |  |  |
| --- | --- | --- |
| **구분** | **Big Endian (빅 엔디안)** | **Little Endian (리틀 엔디안)** |
| **저장 순서** | 상위 바이트부터 (`12` → `34` → `56` → `78`) | 하위 바이트부터 (`78` → `56` → `34` → `12`) |
| **장점** | 사람이 메모리 값을 읽기 직관적임 | CPU의 산술/논리 연산이 더 효율적임 |
| **주요 사용처** | 네트워크 프로토콜 (TCP/IP 등) | 데스크톱/노트북 CPU (Intel, AMD 등) |

C언어에서 포인터 타입을 `char*`로 강제 변환(Casting)한 뒤 메모리 주소를 1바이트씩 출력해 보면, 본인 컴퓨터가 **리틀 엔디안** 방식으로 데이터를 뒤집어서 저장하고 있음을 직접 확인할 수 있습니다\!

## 1\. CISC (Complex Instruction Set Computer)

- **개념:** "복잡하고 많은 명령어 세트를 가진 컴퓨터"
- **철학:** 하드웨어(CPU)가 똑똑해야 한다. 명령어 한 줄로 복잡한 작업을 끝내자\!
- **동작 방식:** 명령어 하나의 길이가 가변적이며, 하나의 명령어가 여러 단계의 복잡한 연산을 수행합니다.
- **장점:** 컴파일러가 만들어내는 코드의 양(프로그램 크기)이 줄어들어 메모리를 아낄 수 있습니다.
- **단점:** CPU 내부 회로가 매우 복잡해지고, 명령어 하나를 실행하는 데 걸리는 시간(클럭 사이클)이 제각각입니다.
- **대표 주자:** **Intel, AMD (x86 아키텍처)** → 우리가 쓰는 대부분의 데스크톱, 노트북 PC

<a id="notion-36f1d46c18fc80d2b6aae9dd8d226129"></a>

## 2\. RISC (Reduced Instruction Set Computer)

- **개념:** "단순하고 감소된 명령어 세트를 가진 컴퓨터"
- **철학:** 명령어를 최대한 단순하게 만들자. 복잡한 건 소프트웨어(컴파일러)가 조합하면 된다\!
- **동작 방식:** 명령어의 길이를 고정하고 종류를 줄였습니다. 모든 명령어가 규칙적이고 단순하게 실행됩니다.
- **장점:** CPU 구조가 단순해서 전력 소모가 적고, 명령어 하나가 1클럭 내외로 빠르게 처리되어 효율적입니다. (파이프라이닝 최적화 유리)
- **단점:** 단순한 명령어를 조합해야 하므로 프로그램 코드의 전체적인 크기가 CISC에 비해 커집니다.
- **대표 주자:** **ARM, Apple Silicon (M1/M2/M3 등)** → 스마트폰, 태블릿, 맥북, 임베디드 장치

<a id="notion-36f1d46c18fc8019829ad9c92c53718b"></a>

## 요약 표

|  |  |  |
| --- | --- | --- |
| **구분** | **CISC (컴퓨터가 복잡함)** | **RISC (명령어가 단순함)** |
| **명령어 수** | 많고 복잡함 (가변 길이) | 적고 단순함 (고정 길이) |
| **연산 방식** | 명령어 하나가 여러 연산 수행 | 단순 명령어 여러 개를 조합하여 수행 |
| **전력 소모** | 비교적 높음 (발열 많음) | 낮음 (효율적인 전력 소모) |
| **주요 장점** | 코드 크기가 작음, 하드웨어 중심 | 속도가 빠름, 전력 효율 좋음, 소프트웨어 중심 |
| **주요 제품** | x86 (Intel Core, AMD Ryzen 등) | ARM (갤럭시/아이폰 AP, Apple M 시리즈) |

> 💡 **최신 트렌드 한마디:** &gt; 최근에는 CISC CPU(Intel) 내부적으로는 RISC 형태로 변환해 실행하고, RISC CPU(ARM)도 성능 향상을 위해 복잡한 기능을 추가하면서 두 방식의 경계가 많이 모호해지고 융합되는 추세입니다.

C언어 코드를 컴파일할 때, 컴파일러는 본인의 컴퓨터 CPU 아키텍처(CISC 또는 RISC)에 맞는 기계어 코드로 변환해 주게 됩니다.

<br>

Unicode(유니코드)와 **UTF-8**을 사용하는 이유는 한마디로 "전 세계 모든 나라의 언어를 깨짐 없이 하나의 표준으로 표현하기 위해서"입니다.

이 둘이 나오기 전에는 국가마다, 컴퓨터마다 문자 인코딩 방식(국내의 경우 EUC-KR 등)이 달라서 해외 사이트에 접속하거나 다른 언어로 된 파일을 열면 글자가 \`\`나 `뷁뷄`처럼 깨지는 현상이 빈번했습니다.

<a id="notion-36f1d46c18fc80b0b472ff285328f555"></a>

## 1\. Unicode (유니코드) 란?

- **정의:** 전 세계의 모든 문자(한글, 영어, 한자, 아랍어, 이모지 등)에 고유한 숫자(코드 포인트)를 부여한 일종의 '문자 지도(사전)'입니다.
- **사용하는 이유:** 과거에는 영어권의 ASCII(7비트)나 한국의 EUC-KR처럼 지역별로 다른 표준을 썼기 때문에, 한 문서에 여러 나라 언어를 쓰면 글자가 깨졌습니다. 이를 해결하기 위해 "전 세계 문자를 단 하나의 표준 숫자로 통일하자\!"고 만든 것입니다.
- **예시:** \* 문자 'A' → 유니코드 주소: `U+0041`

  - 문자 '가' → 유니코드 주소: `U+AC00`

<a id="notion-36f1d46c18fc80d2bd08feb7db07efb3"></a>

## 2\. UTF-8 이란?

- **정의:** 유니코드 사전에 적힌 숫자를 **컴퓨터(메모리)에 실제로 저장하는 방식(인코딩 방식)** 중 하나입니다. 유니코드를 표현하는 가장 인기 있는 방식입니다.
- **사용하는 이유 (핵심 기술: 가변 길이 인코딩):**

  - 유니코드의 모든 문자를 똑같은 크기(예: 4바이트)로 저장하면, 알파벳 'A'(1바이트면 충분함)를 저장할 때도 4바이트를 쓰게 되어 **메모리 낭비가 심각**해집니다.
  - **UTF-8은 문자에 따라 크기를 유연하게 조절(1\~4바이트)합니다.**

    - 영어/숫자는 **1바이트**
    - 한글/한자는 **3바이트**
    - 이모지 등은 **4바이트**

<a id="notion-36f1d46c18fc80f1bd89cd7d36f164f6"></a>

### 💡 왜 이 둘을 함께 써야 할까요? (차이점 직관 이해)

두 개념은 개념적 역할이 완전히 다릅니다.

- **Unicode:** "무슨 문자가 어떤 숫자인지 매핑해 둔 **글자 사전**"
- **UTF-8:** "그 사전에 있는 숫자를 메모리에 **효율적으로 저장하는 방법**"

<a id="notion-36f1d46c18fc80b3a4a8dce8644748d6"></a>

### 요약 표

|  |  |  |
| --- | --- | --- |
| **구분** | **Unicode (유니코드)** | **UTF-8** |
| **역할** | 문자 집합 (Character Set) | 인코딩 방식 (Encoding) |
| **핵심 목적** | 전 세계 문자의 고유 숫자 번호판 표준화 | 유니코드 숫자를 메모리에 효율적으로 저장 |
| **크기** | 논리적인 코드 값 (주소 개념) | 문자에 따라 **1\~4바이트 가변 크기** |
| **가장 큰 장점** | 다국어 지원 (글자 깨짐 문제 완전 해결) | 기존 ASCII(영어)와 완벽 호환, 메모리 절약 |

> 📌 **C언어 관점에서의 팁:**
>
> C언어의 `char` 타입은 1바이트(8비트) 기준입니다. 그래서 UTF-8로 저장된 한글 문자열 "가나다"의 길이를 `strlen()` 함수로 재보면 `3`이 아니라 3바이트씩 3글자여서 \*\*`9`\*\*가 출력됩니다. C언어에서 다국어를 다룰 때 이 인코딩 개념을 모르면 글자 수가 밀리는 버그가 자주 발생합니다\!

# 📌 UTF-8 3바이트 틀 (한글 저장 규칙)

<a id="notion-36f1d46c18fc80b08333cab884ef7f90"></a>

### 1\. 3바이트 틀 개요

유니코드 주소가 `0x0800` \~ `0xFFFF` 사이에 있는 문자(한글, 한자 등)는 UTF-8에서 **무조건 아래의 고정된 틀**을 사용합니다.

1110xxxx  10xxxxxx 10xxxxxx

- **`1110`** <strong>/</strong> **`10`** <strong>/</strong> <strong>`10`</strong>: 컴퓨터가 문자 경계를 인식하기 위한 **국제 표준 고정 표식**
- <strong>`xxxx...`</strong>: 실제 유니코드 비트가 쪼개져 들어가는 **데이터 공간 (총 16비트)**

<a id="notion-36f1d46c18fc80d3a229c42ae7155799"></a>

### 2\. 고정 표식의 역할 (컴퓨터가 해석하는 법)

컴퓨터는 데이터(0과 1)를 1바이트(8비트)씩 읽으면서 첫머리 비트를 보고 글자 크기를 판단합니다.

- **`0xxxxxxx`** <strong>(1바이트 구역):</strong> "첫 비트가 `0`이네? 영어/숫자구나. 1바이트만 읽어야지."
- **`110xxxxx`** <strong>(2바이트 구역):</strong> "첫머리가 `110`이네? 다음 바이트까지 총 2바이트가 한 글자구나."
- **`1110xxxx`** <strong>(3바이트 구역):</strong> "첫머리가 `1110`이네? 다다음 바이트까지 총 3바이트가 한 글자(한글)구나."
- **`10xxxxxx`** <strong>(이어지는 바이트):</strong> "앞이 `10`이네? 나는 혼자서는 의미가 없고, 앞 문자에 종속된 데이터구나."

<a id="notion-36f1d46c18fc80bb8e54c298954f23a8"></a>

### 3\. 핵심 요약 (노션 한 줄 정리)

> **Q. 이 틀은 무조건 고정인가요?**
>
> **A. 네, 100% 고정입니다.** 이 표식이 고정되어 있어야만 컴퓨터가 수많은 데이터 속에서 텍스트 깨짐 없이 영어(1바이트)와 한글(3바이트)의 경계를 정확히 구분하여 읽을 수 있습니다.

**\[유니코드\]**<br>김: AE40 (1010 1110 0100 0000)<br>호: D638 (1101 0110 0011 1000)<br>철: CCA0 (1100 1100 1010 0000)

**\[UTF-8\]**<br>김: 1110\[1010\] 10\[111001\] 10\[000000\]<br>호: 1110\[1101\] 10\[011000\] 10\[111000\]<br>철: 1110\[1100\] 10\[110010\] 10\[100000\]

<br>

```c
#define _CRT_SECURE_NO_WARNINGS // Visual Studio에서 scanf 등 구형 함수의 경고를 끄기 위한 설정

#include <stdio.h>  // 표준 입출력 라이브러리 (printf, scanf, fgets 등)
#include <string.h> // 문자열 처리 라이브러리 (strlen, strcpy, strcmp 등)
#include <stdlib.h> // 표준 유틸리티 라이브러리 (atoi, malloc, free 등)
```

```c
int main(void)
{
	char buff[10];
	int num1, num2;
	char operator;
	int result = 0;

	while (1)
	{
		// 1. 명령 및 안내 메시지 출력
		printf("사칙연산(1+2=) 종료: quit > ");

		// 2. 키보드 입력 받기 (stdin)
		// [quit] 입력 시 buff 저장 방식:
		// index :  0   1   2   3   4   5
		// value : 'q' 'u' 'i' 't' '\n' '\0'
		fgets(buff, sizeof(buff), stdin);

		// 3. 종료 조건 검사
		if (buff[0] == 'q' && buff[1] == 'u' && buff[2] == 'i' && buff[3] == 't')
		{
			printf("프로그램을 종료합니다.\n");
			break;
		}

		// 4. 데이터 변환 (ASCII 문자 -> 정수 int)
		num1 = buff[0] - '0'; // buff[0] - 0x30; 과 동일
		operator = buff[1];
		num2 = buff[2] - '0';

		// 5. 사칙연산 계산
		switch (operator)
		{
		case '+':
			result = num1 + num2;
			break;
		}

		// 6. 결과 출력 (정수 -> ASCII 문자 변환 후 출력)
		printf("%c + %c = %c\n", num1 + '0', num2 + '0', result + '0');
	}

	return 0;
}
```

## 📌 C언어 핵심 문자열 함수 요약 (strncmp, atoi, itoa)

<a id="notion-36f1d46c18fc809d868efdbf491f11c3"></a>

### 1\. strncmp : 문자열 n개 비교

- **기능:** 두 문자열을 지정한 개수(`n`)만큼만 앞에서부터 비교합니다.
- **헤더:** `<string.h>`
- **핵심 활용:** 뒤에 엔터(`\n`)나 쓰레기 값이 붙어 있는 배열에서 앞부분의 특정 키워드(예: `"quit"`)만 정확히 골라내어 비교할 때 안전하게 사용합니다.

```c
strncmp(str1, str2, n);
// 결과가 0이면 -> 지정한 n개 문자열이 완벽히 일치함
```

<a id="notion-36f1d46c18fc8023ab00f225dbc9366b"></a>

### 2\. atoi : 문자열 → 정수 변환 (Ascii To Integer)

- **기능:** 숫자로 된 문자열을 진짜 계산 가능한 정수(`int`)로 변환합니다.
- **헤더:** `<stdlib.h>`
- **핵심 활용:** `fgets()` 등으로 입력받은 문자 배열 `"123"`을 숫자 `123`으로 바꾸어 사칙연산을 하고 싶을 때 사용합니다.

```c
int num = atoi("123"); // num 변수에 정수 123이 저장됨
```

<a id="notion-36f1d46c18fc801b8ee9cf52cb5382b9"></a>

### 3\. itoa : 정수 → 문자열 변환 (Integer To Ascii)

- **기능:** 정수(`int`)를 화면에 출력하거나 전송하기 위해 문자열(문자 배열)로 변환합니다.
- **헤더:** `<stdlib.h>`
- **주의사항:** **비표준 함수**입니다. Windows(Visual Studio) 환경에서는 잘 작동하지만 Linux 등에서는 지원하지 않을 수 있습니다.

```c
char buf[10];
_itoa(123, buf, 10); // 정수 123을 10진수 문자열로 변환하여 buf에 "123" 저장
```

<a id="notion-36f1d46c18fc8088a461dbabac55e6fa"></a>

### 📋 한눈에 보는 요약 표

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **함수명** | **역할** | **입력 형식** | **출력 형식** | **주요 용도** |
| **`strncmp`** | 문자열 부분 비교 | 문자열 2개, 개수 | `0` (일치) 또는 정수 | 명령어 입력 확인 (`"quit"` 검사 등) |
| **`atoi`** | 문자열 → 정수 | `"123"` (문자열) | `123` (`int`) | 문자형 데이터를 숫자로 바꿔 연산할 때 |
| **`itoa`** | 정수 → 문자열 | `123` (`int`) | `"123"` (문자열) | 자릿수가 큰 연산 결과를 문자열로 바꿀 때 |

<a id="notion-36f1d46c18fc8023a2ffd5f22459ca62"></a>

# 📌 C언어 문자열 결합: strcat vs sprintf

두 함수 모두 여러 문자열을 하나로 합칠 때 사용하지만, **작동 방식과 활용 목적**이 완전히 다릅니다.

<a id="notion-36f1d46c18fc808aa46fffb62b74cd43"></a>

## 1\. strcat (String Concatenate)

- **개념:** 기존 문자열의 '맨 끝'을 찾아가서 새로운 문자열을 이어 붙이는 함수입니다.
- **헤더:** `<string.h>`
- **특징:** 대상 버퍼가 반드시 `\0`(Null 문자)로 초기화되어 있어야 안전하게 작동합니다.

<a id="notion-36f1d46c18fc80a8a6c4dc2ac2af20f3"></a>

### 💻 기본 문법 및 예제

```c
char buff[40] = "Hello "; // 반드시 여유 공간이 있어야 함
char str[] = "World";

strcat(buff, str); // buff 뒤에 str을 이어 붙임
// 결과: buff ==> "Hello World"
```

<a id="notion-36f1d46c18fc80a0bfbee4e66c53c4ab"></a>

## 2\. sprintf (String Print Formatted)

- **개념:** `printf`가 모니터 화면에 출력하듯, 그 출력 내용을 **문자열 변수(버퍼)에 그대로 써넣는(저장하는)** 함수입니다.
- **헤더:** `<stdio.h>`
- **특징:** 기존 버퍼에 있던 내용을 **새로 덮어쓰며**, 문자열뿐만 아니라 정수(`%d`), 실수(`%f`) 등 다양한 데이터 타입을 한 번에 조합할 수 있어 활용도가 매우 높습니다.

<a id="notion-36f1d46c18fc800c9132ed0f494472b2"></a>

### 💻 기본 문법 및 예제

```c
char buff[40]; // strcat과 달리 미리 초기화하지 않아도 됨 (덮어쓰기 때문)
char name[] = "철수";
int age = 20;

// 화면에 출력하는 대신 buff 배열에 조립해서 집어넣음
sprintf(buff, "이름: %s, 나이: %d세", name, age);
// 결과: buff ==> "이름: 철수, 나이: 20세"
```

<a id="notion-36f1d46c18fc804fa6b9cdf614d85a98"></a>

## 📋 한눈에 보는 비교 표

|  |  |  |
| --- | --- | --- |
| **구분** | **strcat** | **sprintf** |
| **기능** | 단순 문자열 뒤에 문자열 이어 붙이기 | 다양한 데이터(`%d`, `%s` 등)를 포맷에 맞춰 조립 |
| **필요 헤더** | `<string.h>` | `<stdio.h>` |
| **기존 버퍼 처리** | 기존 문자열 유지하고 **뒤에 추가** | 기존 내용 무시하고 **처음부터 덮어씀** |
| **버퍼 초기화** | 기존 버퍼가 반드시 `\0`로 초기화되어야 함 | 초기화 필요 없음 |
| **추천 용도** | 단어 두 개를 단순히 합칠 때 | 문자열 사이에 공백, 쉼표를 넣거나 숫자를 섞어 합칠 때 |

<a id="notion-36f1d46c18fc803aa8bcdfa93c0547e7"></a>

## 💡 실무 팁 (어떤 걸 써야 할까?)

1. **`strcat`** <strong>연속 사용은 비효율적입니다.</strong>

   - `strcat(buff, a); strcat(buff, b); strcat(buff, c);`를 하면 컴퓨터는 매번 문자열의 처음부터 끝(`\0`)까지 글자 수를 세며 찾아가야 하므로 속도가 느려집니다.
2. <strong>여러 개를 합칠 땐</strong> <strong>`sprintf`</strong>**가 압도적으로 편합니다.**

   - 단어 사이에 공백을 넣거나 문장 형태로 이쁘게 조립하고 싶을 때는 `sprintf(buff, "%s %s %s", a, b, c);` 처럼 한 줄로 처리하는 것이 가독성과 유지보수에 훨씬 좋습니다.

# 📌 C언어 연산자 종류 및 우선순위 표

- **우선순위가 높을수록** 식에서 먼저 계산됩니다.
- **결합 방향**은 같은 우선순위의 연산자가 여러 개 있을 때 왼쪽부터 계산할지(`L → R`), 오른쪽부터 계산할지(`R → L`)를 나타냅니다.

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **우선순위** | **연산자 분류** | **연산자 기호** | **설명** | **결합 방향** |
| **1** | 최우선 연산자 | `()`, `[]`, `->`, `.` | 괄호, 배열, 구조체 참조 | L → R |
| **2** | 단항 연산자 | `!`, `~`, `++`, `--`, `+`, `-`, `*`, `&`, `sizeof` | 논리부정, 증감, 부호, 포인터, 주소 | **R → L** |
| **3** | 산술 (형변환) | `(type)` | 강제 형변환 (Casting) | **R → L** |
| **4** | 산술 (곱/나눗셈) | `*`, `/`, `%` | 곱하기, 나누기, 나머지 구하기 | L → R |
| **5** | 산술 (더/뺄셈) | `+`, `-` | 더하기, 빼기 | L → R |
| **6** | 비트 이동 | `<<`, `>>` | 비트 좌/우 시프트 | L → R |
| **7** | 관계 (대소 비교) | `<`, `<=`, `>`, `>=` | 미만, 이하, 초과, 이상 비교 | L → R |
| **8** | 관계 (동등 비교) | `==`, `!=` | 같다, 다르다 비교 | L → R |
| **9** | 비트 논리 (AND) | `&` | 비트 단위 AND | L → R |
| **10** | 비트 논리 (XOR) | `^` | 비트 단위 XOR | L → R |
| **11** | 비트 논리 (OR) | `\|` | 비트 단위 OR | L → R |
| **12** | 논리 (AND) | `&&` | 조건문 논리 AND (그리고) | L → R |
| **13** | 논리 (OR) | `\|\|` | 조건문 논리 OR (또는) | L → R |
| **14** | 삼항 연산자 | `? :` | 조건 연산자 (`조건 ? 참 : 거짓`) | **R → L** |
| **15** | 대입 연산자 | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=` | 우항의 값을 좌항 변수에 대입/복합대입 | **R → L** |
| **16** | 순차 연산자 | `,` | 콤마 연산자 (나열) | L → R |

<a id="notion-36f1d46c18fc804ab9bfde753b34db85"></a>

## 💡 실무에서 꼭 기억해야 할 3가지 핵심 팁

<a id="notion-36f1d46c18fc80089136d6789cbd386b"></a>

### ① 산술 연산은 `/ %` 가 `+ -` 보다 무조건 먼저입니다.

- 수학 공식과 똑같습니다. `1 + 2 * 3`은 `2 * 3`이 먼저 계산되어 `7`이 됩니다.

<a id="notion-36f1d46c18fc80209f91dbe6f062fc8f"></a>

### ② 대입 연산자(`=`)와 삼항 연산자는 우측부터 계산합니다 (`R → L`).

- `a = b = c = 5;` 라는 코드가 있다면 맨 오른쪽인 `c = 5`부터 시작해서 `b = c`, `a = b` 순서로 값이 채워집니다.

<a id="notion-36f1d46c18fc80c6a445e30c1179e0f7"></a>

### ③ 헷갈릴 때는 무조건 괄호 `()` 가 치트키입니다.

- 연산자 우선순위를 전 세계 모든 개발자가 완벽하게 외우고 코딩하지 않습니다. 조금이라도 계산 순서가 헷갈리거나 의도가 명확해야 할 때는 **우선순위가 가장 높은 괄호**<strong>`()`</strong>**로 묶어버리는 것이 가독성과 버그 방지에 최고**입니다.

  - 예: `if ((a > 5) && (b < 10))`
