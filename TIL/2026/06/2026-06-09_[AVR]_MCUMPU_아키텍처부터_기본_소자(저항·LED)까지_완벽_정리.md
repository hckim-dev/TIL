# 💻 임베디드 시스템 기초: MCU와 MPU

<a id="notion-37a1d46c18fc801d9653c9ee8a51aa43"></a>

## 1\. 마이크로컨트롤러(MCU)란?

> 💡 **한 줄 요약:** 하나의 칩(Chip) 안에 CPU, 메모리, 입출력 장치가 모두 들어있는 **'초소형 컴퓨터'**

- **정의:** MicroController Unit의 약자로, 특정 장치를 제어(Control)하기 위해 만들어진 마이크로컴퓨터입니다.
- **특징:**

  - **All-in-One:** CPU뿐만 아니라 데이터를 저장하는 메모리(RAM, ROM), 외부 장치와 연결하는 입출력 포트(GPIO)가 하나의 칩에 통합되어 있습니다.
  - **목적성:** 스마트폰이나 PC처럼 다양한 프로그램을 실행하는 것이 아니라, 밥솥, 세탁기, 마우스, ATmega128A 보드처럼 정해진 한 가지 기능(기기 제어)을 수행하는 데 특화되어 있습니다.
  - **장점:** 크기가 작고, 가격이 저렴하며, 소비 전력이 매우 적습니다.

<a id="notion-37a1d46c18fc80c7ab95c89c141a2118"></a>

## 2\. 마이크로컨트롤러(MCU) vs 마이크로프로세서(MPU)

두 장치는 모두 시스템의 '두뇌' 역할을 하지만, **칩의 구성 방식**과 **사용 목적**에서 큰 차이가 있습니다.

<a id="notion-37a1d46c18fc8037bd30d6d86990946a"></a>

### 📊 한눈에 비교하는 핵심 차이점

|  |  |  |
| --- | --- | --- |
| **구분** | **마이크로컨트롤러 (MCU)** | **마이크로프로세서 (MPU)** |
| **핵심 개념** | 하나의 칩에 컴퓨터 부품을 모두 넣음 (원칩) | 고성능 연산 장치(CPU) 기능에만 집중 |
| **칩의 구성** | CPU + RAM + ROM + I/O 단자 가 **내장** | RAM, ROM, I/O 단자를 **외부에 따로 연결**해야 함 |
| **주요 용도** | 가전제품, 자동차 제어, IoT 기기, 로봇 | PC, 스마트폰, 서버, 고성능 그래픽 처리 |
| **성능 (클럭)** | 비교적 낮음 (몇 MHz \~ 수백 MHz) | 매우 높음 (몇 GHz 이상) |
| **운영체제(OS)** | OS가 없거나 가벼운 RTOS 사용 | Windows, Linux, Android 등 대형 OS 필수 |
| **가격 및 전력** | 저렴하고 소비 전력이 매우 낮음 | 비싸고 소비 전력이 높음 (발열 관리 필요) |
| **대표 예시** | **ATmega128A**, Arduino, STM32 | Intel Core 시리즈, AMD Ryzen, Apple M 시리즈 |

<a id="notion-37a1d46c18fc8018ac0afda9dae3d0e8"></a>

### 🔍 조금 더 자세히 알아보기

📢 **1\. 칩 구성 방식의 차이 (원칩 vs 멀티칩)**

- **MCU:** 방 하나에 침대(RAM), 책상(ROM), 컴퓨터(CPU)가 다 들어있는 '원룸'과 같습니다. 공간은 좁지만 동선이 짧고 효율적입니다.
- **MPU:** 거실에는 CPU가 있고, 안방에는 RAM이 있고, 건너방에는 SSD가 있는 '큰 아파트'와 같습니다. 성능은 뛰어나지만 구조가 복잡하고 주변 부품들이 반드시 같이 있어야 작동합니다.

📢 **2\. 실행하는 소프트웨어의 차이**

- **MCU:** 전원이 켜지면 내가 C언어로 작성해서 집어넣은 단 하나의 main 루프(무한 반복문)만 실행합니다. 윈도우 같은 화면이 뜰 필요 없이 바로 작동해야 하기 때문입니다.
- **MPU:** 컴퓨터를 켜면 Windows나 Linux 같은 무거운 운영체제(OS)를 먼저 메모리에 올린 뒤, 그 위에서 인터넷 브라우저, 게임, 문서 프로그램 등 **여러 프로그램을 동시에(멀티태스킹)** 실행합니다.

## 🔍 각 항목별 상세 설명

<a id="notion-37a1d46c18fc80b78327e80ac306cd85"></a>

### 1\. 비트 (Bit): 8비트 vs 64비트

> 💡 **데이터 처리 도로의 폭 (차선 수)**

- **8비트 (ATmega128):** CPU가 한 번에 처리할 수 있는 데이터의 크기가 8비트(2^8 = 256가지 상태)입니다. 숫자로 치면 0부터 255까지의 숫자만 한 번에 처리할 수 있습니다.

  - *임베디드 관점:* 센서 값을 읽거나 LED를 켜고 끄는 등의 제어 작업에는 8비트만으로도 충분히 차고 넘칩니다.
- **64비트 (Core i7):** 한 번에 64비트라는 어마어마한 양의 데이터를 처리합니다.

  - *PC 관점:* 고화질 영상, 복잡한 3D 게임, 대용량 프로그램을 매끄럽게 처리하기 위해 압도적으로 넓은 데이터 도로가 필요합니다.

<a id="notion-37a1d46c18fc809da60cd02652e6a65e"></a>

### 2\. 메모리 (Memory): 128 KB vs 8 GB

> 💡 **데이터 저장하고 작업하는 공간의 크기**

- **128 KB (ATmega128):** 코드가 저장되는 공간(플래시 메모리)이 128KB입니다. 요즘 스마트폰으로 찍는 사진 한 장이 보통 3\~5MB(3000\~5000KB)인 것을 감안하면 매우 작은 용량입니다.

  - *임베디드 관점:* 윈도우 같은 OS 없이 오직 내가 짠 C언어 코드만 들어가기 때문에, 효율적으로 코딩하면 128KB는 로봇 한 대를 완벽히 제어하고도 남는 공간입니다. (참고로 연산용 RAM은 단 4KB입니다.)
- **8 GB (Core i7):** 8GB는 대략 8,388,608 KB입니다. ATmega128 메모리의 **약 65,000배**에 달합니다.

  - *PC 관점:* 크롬 브라우저, 카카오톡, 개발 툴, 유튜브 영상 등을 동시에 띄워두고 작업(멀티태스킹)해야 하므로 거대한 메모리가 필수입니다.

<a id="notion-37a1d46c18fc808b8c6ae189c4caef90"></a>

### 3\. 클록 (Clock): 16 MHz vs 3.4 GHz (쿼드 코어)

> 💡 **CPU의 일 처리 속도 (1초에 치는 박수 횟수)**

- **16 MHz (ATmega128):** 메가(M)는 백만을 뜻합니다. 즉, ATmega128은 **1초에 1,600만 번**의 신호(박수)를 만들며 일을 합니다.

  - *임베디드 관점:* 숫자는 작아 보이지만, 스위치가 눌렸는지 감지하거나 LED를 깜빡이는 속도로는 인간이 인지할 수 없을 만큼 엄청나게 빠른 속도입니다.
- **3.4 GHz 쿼드 코어 (Core i7):** 기가(G)는 10억을 뜻합니다. 3.4GHz는 **1초에 34억 번** 박수를 친다는 의미입니다. 게다가 이런 손(Core)이 4개(Quad)나 있어서 동시에 일을 나눠서 합니다.

  - *PC 관점:* 복잡한 3D 그래픽 연산이나 수십억 개의 수학 계산을 순식간에 끝내기 위해 초고속 클록과 멀티코어가 필요합니다.

## 직렬 통신의 분류: 동기식 vs 비동기식

> 💡 **직렬 통신이란?** 데이터를 1개의 선(Line)을 통해 한 비트씩 차례대로 보내는 통신 방식입니다. ATmega128A에서 외부 장치와 대화할 때 가장 많이 씁니다.

<a id="notion-37a1d46c18fc80c4b5f3dc6a730f4adc"></a>

### 🔄 동기식 통신 (Synchronous)

- **정의:** 데이터를 보내는 쪽과 받는 쪽이 **동일한 클록(Clock) 신호**에 발을 맞추어 데이터를 송/수신하는 방식입니다.
- **특징:**

  - 데이터를 주고받는 선 외에, 박자를 맞춰주기 위한 **'클록 전용 선'이 반드시 추가로 필요**합니다.
  - 송신측이 클록 신호를 쾅, 쾅, 쾅 쳐줄 때마다 수신측은 그 타이밍에 맞춰 데이터를 정확히 읽어갑니다.
  - 비동기식에 비해 속도가 대단히 빠르고 정확합니다.
- **대표 예시:** SPI 통신, I2C 통신

<a id="notion-37a1d46c18fc807f85e9ebeebb41fa14"></a>

### 🚫 비동기식 통신 (Asynchronous)

- **정의:** 클록 신호선 없이, 데이터를 보내는 쪽과 받는 쪽이 **독립적으로 약속된 속도**로 데이터를 송/수신하는 방식입니다.
- **특징:**

  - 클록 선이 필요 없기 때문에 **통신 선의 개수가 줄어든다는 강력한 장점**이 있습니다. (기본적으로 데이터 선 1개만 있으면 됨)
  - 대신 박자를 맞춰줄 기준이 없기 때문에, 데이터를 보낼 때 "이제 데이터 시작한다\!"라는 신호(**Start Bit**)와 "이제 끝났다\!"라는 신호(**Stop Bit**)를 앞뒤로 붙여서 보냅니다.
  - 서로 약속한 통신 속도(Baud Rate, 보오레이트)가 조금이라도 어긋나면 데이터가 완전히 깨집니다.
- **대표 예시:** **UART 통신**

<a id="notion-37a1d46c18fc80fea052dd2cbedb3daf"></a>

## 2\. 주파수와 클록 단위: Hz (헤르츠)

> 💡 **Hz란?** 1초 동안 신호(진동 또는 박수)가 반복되는 횟수를 말합니다. MCU의 심장박동 속도라고 생각하면 쉽습니다.

- **신호의 변화와 주기:** \* 신호가 '0(Low)'에서 '1(High)'로 올라갔다가 다시 '0'으로 내려오는 한 번의 세트를 1주기(Cycle)라고 합니다.

  - **1 Hz:** 1초에 이 변화가 딱 1번 일어남.
- **ATmega128A의 16 MHz 적용해보기:**

  - 메가(M)는 백만(1,000,000)을 의미하므로, **16 MHz는 1초에 신호 변화가 1,600만 번 일어난다**는 뜻입니다.
  - 즉, ATmega128A는 1초에 1,600만 번 박수를 치며, 한 번 박수를 칠 때마다 C언어 명령어(코드)를 거의 한 줄씩 처리합니다.

<a id="notion-37a1d46c18fc8054951ceb3877f4f5b7"></a>

## 📌 초보 개발자를 위한 한 걸음 더\!

> **비동기식 통신을 쓸 때 '클록 속도(Hz)'가 중요한 이유**
>
> 비동기식(UART)은 클록 선이 없어서 "서로 약속한 속도"가 중요하다고 했습니다. PC와 ATmega128A가 통신할 때, 보통 9600 bps(1초에 9600비트 송신)라는 속도를 많이 씁니다.
>
> 이때 ATmega128A는 자신의 내부 클록인 \*\*16 MHz(1초에 1,600만 번 쪼개는 시간)\*\*를 정확히 계산해서 나눈 뒤, 정확한 타이밍에 9600 bps 속도로 데이터를 밀어내야 합니다.
>
> 그래서 비동기식 통신을 공부할 때도 결국 MCU의 메인 클록 속도(Hz)를 완벽히 이해하고 있어야 통신 에러를 막을 수 있습니다\!

# 🧠 CPU 아키텍처 비교: CISC vs RISC

> 💡 **핵심 요약**
>
> - **CISC (컴퓨터 명령어 백과사전):** 복잡하고 다양한 명령어를 미리 지니고 있어, 한 번의 명령으로 많은 일을 처리하는 방식 (데스크톱 PC 중심)
> - **RISC (컴퓨터 명령어 요약본):** 자주 쓰는 핵심 명령어만 남겨 가볍게 만들고, 이를 빠르게 조합해서 처리하는 방식 (스마트폰, **ATmega128A** 중심)

<a id="notion-37a1d46c18fc803a827ff3d7562ad853"></a>

## 📊 한눈에 보는 핵심 비교 테이블

|  |  |  |
| --- | --- | --- |
| **구분** | **CISC (Complex Instruction Set Computer)** | **RISC (Reduced Instruction Set Computer)** |
| **명령어 종류** | 매우 많고 복잡함 | 적고 단순함 |
| **명령어 길이** | 가변형 (명령어마다 길이가 다름) | 고정형 (모든 명령어 길이가 같음) |
| **설계 철학** | "소프트웨어가 짜기 편하게 하드웨어를 복잡하게 만들자" | "하드웨어를 가볍게 유지하고 소프트웨어로 해결하자" |
| **처리 속도** | 명령어 하나를 처리하는 데 여러 클록 소요 | **명령어 하나를 1클록에 처리** (파이프라이닝 최적화) |
| **전력 및 발열** | 높음 (회로가 복잡해서 전기를 많이 먹음) | **낮음** (회로가 단순해서 저전력/저발열에 유리) |
| **하드웨어 크기** | 칩의 구조가 크고 복잡함 | 칩의 구조가 작고 효율적임 |
| **대표 제품** | Intel Core 시리즈, AMD Ryzen (PC/서버용) | <strong>ATmega128A (AVR)</strong>, Apple M 시리즈, ARM 계열 (스마트폰/임베디드) |

<a id="notion-37a1d46c18fc80718399e819d9c1caea"></a>

## 🔍 비유로 이해하는 CISC와 RISC

명령어 집합을 설계하는 철학의 차이를 이해하면 쉽습니다.

- **🏛️ CISC는 '다기능 만능 칼'입니다.**

  - "감자 깎기", "병따개", "와인 오프너" 기능이 칼 하나에 다 들어있습니다.
  - 장점: 와인을 딸 때 "와인 오프너 꺼내\!"라는 복잡한 명령어 딱 한 번만 내리면 됩니다.
  - 단점: 칼 자체의 덩치가 커지고 무거우며, 잘 쓰지 않는 기능 때문에 가격이 비싸집니다.
- **🔪 RISC는 '잘 드는 기본 식칼'입니다.**

  - 칼에는 오직 "자르기"라는 기본 기능만 있습니다.
  - 장점: 칼이 매우 가볍고 단순하며 가격이 저렴합니다. 전력 소모도 적습니다.
  - 단점: 와인을 따려면 "코르크에 칼끝을 넣는다", "돌린다", "잡아당긴다"처럼 기본 명령어를 여러 개 조합해서 지시해야 하므로 소프트웨어(컴파일러)가 할 일이 많아집니다.

<a id="notion-37a1d46c18fc80ae95f8d3222eea7ec8"></a>

## ⚙️ 작동 방식의 차이: 1클록(Clock)의 비밀

우리가 다루는 **ATmega128A는 RISC 구조**를 채택하고 있습니다. 왜 임베디드에서는 RISC를 선호할까요?

- **CISC의 명령어 처리:**

  - 명령어의 크기와 형태가 제각각이라, CPU가 명령어를 받아서 분석하는 데 시간이 오래 걸립니다. 하나의 명령어를 실행하는 데 5클록, 10클록씩 걸리기도 합니다.
- **RISC의 명령어 처리:**

  - 모든 명령어의 규격과 길이가 똑같습니다. CPU 입장에서는 머리 쓸 필요 없이 기계적으로 툭, 툭 처리하면 됩니다.
  - 덕분에 ATmega128A는 **대부분의 명령어를 단 1클록(Clock)만에 실행**합니다. 16 MHz 클록을 쓰면 1초에 거의 1,600만 개의 명령어를 오차 없이 정확한 타이밍에 실행할 수 있는 비결이 바로 이 RISC 구조 덕분입니다.

<a id="notion-37a1d46c18fc8084b616dd6fcaed9ffa"></a>

## 📌 임베디드 공부를 위한 핵심 포인트

> **"ATmega128A가 RISC인 이유를 기억하세요\!"**
>
> 스마트 워치, 무선 센서 등 임베디드 기기는 배터리 하나로 며칠, 몇 달을 버텨야 합니다. 회로가 단순해서 전기를 대단히 적게 먹고, 가격이 싸며, 제어 타이밍이 정확한 RISC(AVR 아키텍처)가 임베디드 시스템에 가장 완벽한 짝꿍이기 때문입니다.

<a id="notion-37a1d46c18fc80d0a4a6c27036778d8e"></a>

# 🏗️ 컴퓨터 구조의 양대산맥: 폰노이만 구조 vs 하버드 구조

> 💡 **핵심 요약**
>
> - **폰노이만 구조:** 소스코드(명령어)와 데이터가 \*\*하나의 메모리, 하나의 버스(통로)\*\*를 공유하는 방식 (일반적인 PC 구조)
> - **하버드 구조:** 소스코드 전용 메모리/통로와 데이터 전용 메모리/통로를 **각각 독립적으로 분리**한 방식 (**ATmega128A** 구조)

<a id="notion-37a1d46c18fc8043b4b1c5f6b3f9b0f3"></a>

## 📊 한눈에 보는 핵심 비교 테이블

|  |  |  |
| --- | --- | --- |
| **구분** | **폰노이만 구조 (Von Neumann Architecture)** | **하버드 구조 (Harvard Architecture)** |
| **메모리 구성** | 명령어와 데이터가 **하나의 메모리**에 있음 | 명령어 메모리와 데이터 메모리가 **물리적으로 분리**됨 |
| **데이터 통로 (Bus)** | 통로가 **1개** (공유함) | 통로가 **2개** (명령어 버스 / 데이터 버스 분리) |
| **작동 방식** | 명령어를 읽을 때는 데이터를 읽을 수 없음 (교대 처리) | 명령어를 읽는 동시에 데이터를 읽고 쓸 수 있음 (동시 처리) |
| **처리 속도** | 비교적 느림 (병목 현상 발생 가능) | **비교적 빠름** (고속 처리에 유리) |
| **하드웨어 복잡도** | 구조가 단순하고 비용이 저렴함 | 구조가 복잡하고 회로 설계 비용이 더 듦 |
| **대표 예시** | 데스크톱 PC (Intel, AMD 등), 범용 컴퓨터 | <strong>ATmega128A (AVR)</strong>, DSP, 스마트폰 AP의 일부 구조 |

<a id="notion-37a1d46c18fc804f9b14de4d42608fd1"></a>

## 🔍 그림과 비유로 이해하기

<a id="notion-37a1d46c18fc8012aa61fcabb8ed1ead"></a>

### 좁은 1차선 도로 vs 뚫려있는 2차선 도로

- **🛣️ 폰노이만 구조는 '1차선 왕복 도로'입니다.**

  - "명령어 트럭"과 "데이터 트럭"이 하나의 도로(Bus)를 같이 써야 합니다.
  - 따라서 명령어 트럭이 지나가는 동안에는 데이터 트럭이 지나가지 못하고 뒤에서 기다려야 합니다. 이를 '폰노이만 병목 현상(Bottleneck)'이라고 부릅니다.
  - 하지만 도로를 하나만 깔면 되기 때문에 칩을 만들 때 구조가 단순하고 가격이 쌉니다.
- **🛣️ 하버드 구조는 '명령어 전용 차선'과 '데이터 전용 차선'이 분리된 고속도로입니다.**

  - 명령어 메모리로 가는 길과 데이터 메모리로 가는 길이 아예 따로 레이스가 펼쳐져 있습니다.
  - CPU가 다음 실행할 명령어를 읽어오는 동시에, 지금 필요한 데이터를 저장하거나 읽을 수 있습니다. 서로 간섭이 없기 때문에 속도가 대단히 빠릅니다.

<a id="notion-37a1d46c18fc80949fcaecd9908b0ca2"></a>

## ⚙️ ATmega128A 스펙으로 직접 확인하는 하버드 구조

우리가 공부할 **ATmega128A의 스펙**을 보면 이 하버드 구조가 눈에 바로 보입니다. 앞서 정리했던 메모리 스펙을 다시 보면 이해가 쉽습니다.

- **플래시 메모리 (Flash Memory) - 128 KB:** 내가 작성한 C언어 소스코드(명령어)가 저장되는 전용 공간입니다.
- **SRAM - 4 KB:** 코드 내부에서 쓰이는 **변수나 데이터**가 실시간으로 저장되고 삭제되는 전용 공간입니다.

> 💡 만약 ATmega128A가 폰노이만 구조였다면 그냥 '통합 메모리 132 KB' 구조였겠지만, 하버드 구조를 채택했기 때문에 코드 공간(128KB)과 데이터 공간(4KB)의 메모리가 **물리적으로 완전히 쪼개져 있는 것**입니다.

<a id="notion-37a1d46c18fc8047963de1168d79b1c6"></a>

## 📌 임베디드 공부를 위한 핵심 포인트

> **"RISC와 하버드 구조의 시너지"**
>
> ATmega128A가 속도가 빠른 **RISC 아키텍처**를 가질 수 있었던 일등 공신이 바로 **하버드 구조**입니다.
>
> 명령어를 가져오는 통로와 데이터를 가져오는 통로가 분리되어 있기 때문에, CPU는 쉴 틈 없이 다음 명령어를 밀어 넣는 '파이프라이닝(Pipelining)' 기법을 쓸 수 있고, 덕분에 1클록당 1명령어 처리라는 엄청난 효율을 낼 수 있게 됩니다.

<br>

<a id="notion-37a1d46c18fc802e9652ed6e823fb3f1"></a>

# 💾 메모리의 종류: ROM, RAM, SRAM, DRAM 완전 정복

> 💡 **핵심 요약**
>
> - **ROM (비휘발성):** 전원이 꺼져도 데이터가 지워지지 않는 방 (소스코드 저장용)
> - **RAM (휘발성):** 전원이 꺼지면 데이터가 싹 날아가는 작업대 (실시간 변수/데이터 처리용)
> - **SRAM:** 속도가 엄청나게 빠르고 제어가 단순함 (**ATmega128A 내부 RAM**으로 사용)
> - **DRAM:** 용량이 크고 저렴하지만 주기적으로 충전이 필요함 (일반 PC용 RAM)

<a id="notion-37a1d46c18fc808b842de140354ac893"></a>

## 📊 한눈에 보는 핵심 비교 테이블

|  |  |  |
| --- | --- | --- |
| **구분** | **ROM (Read Only Memory)** | **RAM (Random Access Memory)** |
| **휘발성 여부** | **비휘발성** (전원이 꺼져도 유지) | **휘발성** (전원이 꺼지면 소멸) |
| **주요 역할** | MCU의 전원이 켜졌을 때 실행할 **소스코드 저장** | 프로그램 실행 중 필요한 **임시 변수/데이터 저장** |
| **속도** | 상대적으로 느림 | 상대적으로 매우 빠름 |
| **ATmega128A 예시** | **플래시 메모리 (128 KB)** | **내부 SRAM (4 KB)** |

<a id="notion-37a1d46c18fc80f5b728f7c7bdf4f9fa"></a>

## 🔍 RAM의 두 형제: SRAM vs DRAM 상세 비교

RAM은 만드는 방식과 회로 구조에 따라 크게 **SRAM**과 **DRAM**으로 나뉩니다.

|  |  |  |
| --- | --- | --- |
| **항목** | **SRAM (Static RAM)** | **DRAM (Dynamic RAM)** |
| **특징** | 정적 RAM (전원만 있으면 데이터 유지) | 동적 RAM (시간이 지나면 데이터가 사라짐) |
| **핵심 구조** | 플립플롭 회로 (트랜지스터 4\~6개 사용) | 커패시터(축전기) 1개 + 트랜지스터 1개 사용 |
| **리프레시(재충전)** | **필요 없음** | **주기적으로 필수** (방전되면 데이터 손실) |
| **속도** | **압도적으로 빠름** | SRAM에 비해 느림 |
| **용량 및 가격** | 구조가 복잡해 대용량이 어렵고 **비쌈** | 구조가 단순해 대용량이 가능하고 **저렴함** |
| **주요 사용처** | CPU 내부 캐시 메모리, **MCU(ATmega128A) 내부 RAM** | PC 메인 메모리 (우리가 흔히 사는 8GB, 16GB RAM) |

<a id="notion-37a1d46c18fc80489ecef6e037cd1c36"></a>

## ⚙️ 개념 상세 설명

<a id="notion-37a1d46c18fc805db16bed5d7d151a16"></a>

### 1\. ROM: 지워지지 않는 기억 장치

- 컴퓨터를 끄면 하드디스크의 파일이 그대로 남아있듯, MCU의 전원을 꺼도 우리가 업로드한 C언어 코드가 지워지면 안 됩니다. 이 코드가 저장되는 공간이 바로 ROM(그중에서도 플래시 메모리)입니다.
- 이름은 '읽기 전용'이지만, 컴퓨터에서 다운로더(ISP)를 통해 코드를 구울 때(Write)는 데이터를 쓸 수 있습니다. 단, 실행 중인 코드가 실시간으로 값을 바꾸지는 못합니다.

<a id="notion-37a1d46c18fc8080919bf892e884090c"></a>

### 2\. SRAM: 속도로 승부하는 메모리

- ATmega128A 내부에 들어있는 RAM입니다. 전기가 공급되는 동안에는 데이터가 완벽하게 유지됩니다.
- 회로가 복잡해서 칩의 공간을 많이 차지하기 때문에 ATmega128A에는 딱 **4 KB**라는 아주 작은 용량만 들어있습니다. 대신 속도가 CPU와 맞먹을 정도로 엄청나게 빨라 MCU 제어에 최적입니다.

<a id="notion-37a1d46c18fc80219257c7fc9b575c44"></a>

### 3\. DRAM: 가성비와 용량으로 승부하는 메모리

- 내부의 아주 작은 배터리(커패시터)에 전기를 채워서 데이터를 기억하는 방식입니다. 문제는 이 전기가 순식간에 자연 방전됩니다.
- 그래서 데이터가 안 날아가도록 **1초에 수백 번씩 전기를 다시 채워주는 '리프레시(Refresh)' 작업**을 하드웨어적으로 계속 해줘야 합니다. 제어는 복잡하지만 칩을 작고 싸게 만들 수 있어, PC처럼 기가바이트(GB) 단위의 대용량 메모리가 필요할 때 사용합니다.

<a id="notion-37a1d46c18fc804a89aad2bbb67ffcf5"></a>

## 📌 핵심 포인트

> **"내가 만든 변수는 어디로 갈까?"**
>
> ATmega128A 코딩을 할 때 아래의 흐름을 머릿속에 그리시면 좋습니다.
>
> 1. 내가 짠 소스코드는 \*\*플래시 메모리(ROM)\*\*에 저장되어 영구히 보존됩니다.
> 2. 코드 안에서 선언한 `int a = 10;` 같은 변수들은 MCU가 켜진 뒤 \*\*SRAM(RAM)\*\*에 자리를 잡고 실시간으로 값이 바뀝니다.
> 3. 전원을 끄면 `a`라는 변수는 사라지지만, 소스코드는 ROM에 그대로 남아있으므로 다음 구동 때 다시 정상 작동합니다.

# 🔌 MCU의 손과 발: GPIO (General Purpose Input/Output)

> 💡 **한 줄 요약**
>
> - **GPIO:** 프로그램(C언어)으로 그 기능을 마음대로 바꾸어 쓸 수 있는 **'다목적 입출력 핀(다리)'**
> - MCU 칩에 달린 수많은 다리 중에서, 전기를 내보내거나(Output) 들어오는 전기를 읽는(Input) 용도로 쓰는 핀들을 말합니다.

<a id="notion-37a1d46c18fc80d9a2fece0000ba6aca"></a>

## 1\. GPIO의 핵심 개념

일반적인 PC의 메인보드를 보면 USB 포트(마우스용), HDMI 포트(모니터용), 랜선 포트(인터넷용)처럼 각 구멍의 용도가 미리 정해져 있습니다.

반면, **MCU의 GPIO 핀은 태어날 때 용도가 정해져 있지 않습니다.** 내가 C언어 코드로 어떻게 설정하느야에 따라 변신하는 카멜레온 같은 핀입니다.

- **출력(Output) 모드 설정 시:** 핀으로 전기를 내보냅니다. (예: LED 켜기, 모터 돌리기, 부저 울리기)
- **입력(Input) 모드 설정 시:** 핀으로 전기가 들어오는지 감지합니다. (예: 스위치 눌림 감지, 센서 값 읽기)

<a id="notion-37a1d46c18fc803dbff4d914c3320d5b"></a>

## 2\. ATmega128A의 GPIO와 3대 레지스터

ATmega128A로 첫 실습(LED 깜빡이기)을 할 때 무조건 쓰게 되는 3가지 레지스터(설정 변수)가 있습니다. 이 3개의 이름은 무조건 외우셔야 합니다.

<a id="notion-37a1d46c18fc808a877aff440f86c81f"></a>

### ① DDR (Data Direction Register) — "방향 결정"

- 핀을 **입력**으로 쓸지, **출력**으로 쓸지 '방향'을 결정하는 레지스터입니다.
- 비트 값을 <strong>`1`</strong><strong>로 바꾸면 출력(Output)</strong>, `0`으로 바꾸면 입력(Input)으로 설정됩니다.
- *예시:* `DDRA = 0xFF;` ➡️ A 포트의 모든 핀을 출력용으로 쓰겠다\!

<a id="notion-37a1d46c18fc8067bcd1e35179a9b34a"></a>

### ② PORT (Data Register) — "출력 값 결정"

- DDR에서 '출력'으로 설정된 핀에 **실제로 전기를 보낼지 말지** 결정하는 레지스터입니다.
- 비트 값을 <strong>`1`</strong><strong>로 주면 5V 전기가 나아가고(High)</strong>, <strong>`0`</strong>**으로 주면 0V로 전기가 끊깁니다(Low).**
- *예시:* `PORTA = 0x01;` ➡️ A 포트의 0번 핀에 5V 전기를 보내서 연결된 LED를 켜겠다\!

<a id="notion-37a1d46c18fc808894bbcf5bfb211820"></a>

### ③ PIN (Input Pins Address) — "입력 값 읽기"

- DDR에서 '입력'으로 설정된 핀에 **지금 전기가 들어오고 있는지 매순간 확인**하는 레지스터입니다.
- 외부에서 전기가 들어오고 있으면 <strong>`1`</strong>, 안 들어오면 `0`으로 실시간 저장됩니다. (우리는 코드로 이 값을 읽기만 하면 됩니다.)
- *예시:* `if(PINA & 0x01)` ➡️ A 포트의 0번 핀에 스위치가 눌려 전기가 들어왔는지 확인하겠다\!

<a id="notion-37a1d46c18fc80258890cfe87183c694"></a>

## 🏢 포트(Port)란 또 무슨 뜻인가요?

ATmega128A의 핀 맵을 보면 `PA0`, `PA1`, `PB0`, `PC0` 같은 글자가 적혀 있습니다.

- GPIO 핀은 낱개로 다루면 너무 많아서 복잡하기 때문에, **8개씩 묶어서 '포트(Port)'라는 그룹**으로 관리합니다.
- 8비트(2^8) MCU이기 때문에 8개씩 묶는 것이 데이터 처리 효율에 가장 좋기 때문입니다.
- A그룹은 **PORTA**, B그룹은 **PORTB**라고 부르며, 각 그룹 안에는 0번부터 7번까지 총 8개의 핀이 존재합니다.

<a id="notion-37a1d46c18fc801bb63dec37c364e1c5"></a>

## 📌 한 줄 요약

> **"GPIO 제어는 DDR로 방향을 정하고, PORT로 전기를 내보내며, PIN으로 전기를 읽는 하드웨어 제어의 첫걸음이다\!"**

# 🔌 전자 회로의 핵심 부품: 저항(Resistor) 완전 정복

> 💡 **한 줄 요약:** 전기의 흐름(전류)을 방해하여 회로의 안전을 지키고, 전압과 전류를 원하는 크기로 조절하는 가장 기본적이고 중요한 전자 부품입니다.

<a id="notion-37a1d46c18fc80b38002c61b6cf81049"></a>

## 1\. 저항의 단위와 기호

- **기호:** 회로도에서는 주로 `R`로 표시합니다.
- **단위:** **옴 (Ω, Ohm)** 단위를 사용합니다.

  - 1,000 Ω = 1 kΩ (킬로옴)
  - 1,000,000 Ω = 1 MΩ (메가옴)
- **기본 원리 (옴의 법칙):** 전류는 전압에 비례하고 저항에 반비례합니다. 즉, **저항(Ω) 값이 커질수록 흐르는 전기의 양(전류)은 줄어듭니다.**

<a id="notion-37a1d46c18fc802cab13e24365819068"></a>

## 2\. 저항이 회로에서 하는 진짜 역할 (3가지)

<a id="notion-37a1d46c18fc80b28ad5f054ced54990"></a>

### ① 과전류 방지 (전류 제한) ➡️ *부품 타는 것 방지*

모든 전자 부품(LED, MCU 칩 등)은 버틸 수 있는 최대 전기가 정해져 있습니다.

- 만약 저항 없이 ATmega128A의 5V 전원을 LED에 바로 연결하면, 너무 강한 전기가 한 번에 콸콸 흘러서 LED가 '퍽' 하고 타버립니다.
- 이때 선 중간에 저항을 달아주면, 저항이 전기 흐름을 꽉 붙잡아주어 LED가 안전하게 켤 수 있을 만큼의 적당한 전기만 흐르게 만듭니다.

<a id="notion-37a1d46c18fc80268adffc27e66415b1"></a>

### ② 전압 분배 ➡️ *원하는 전압 만들기*

MCU는 5V로 작동하는데, 어떤 센서는 반드시 3.3V만 받아야 할 때가 있습니다.

- 이때 저항 2개를 직렬로 연결하면, 저항의 비율에 따라 5V 전압이 쪼개지게 됩니다.
- 이 원리를 이용해 5V 전기를 3.3V나 2.5V 등 개발자가 원하는 전압으로 낮춰서 센서에 안전하게 공급할 수 있습니다.

<a id="notion-37a1d46c18fc802baf3de12a3a6f3411"></a>

### ③ 풀업(Pull-up) / 풀다운(Pull-down) ➡️ *노이즈 제거*

스위치를 눌렀을 때 MCU 입력 핀에 전기 신호를 정확하게 전달하기 위해 씁니다.

- 스위치를 떼고 있을 때, 선이 공중에 붕 떠서 주변 정전기 때문에 값이 0과 1 사이를 미친 듯이 출렁거리는 오작동(플로팅 현상)이 발생합니다.
- 이때 저항을 이용해 선을 5V나 GND 쪽에 살짝 묶어두면, 스위치를 안 누를 때는 신호가 완벽하게 고정되어 오작동을 완전히 막아줍니다.

<a id="notion-37a1d46c18fc80949107c7d9a1364e19"></a>

## 🎨 3. 저항 값 읽는 법 (색띠 읽기)

실습용 저항을 보면 몸통에 알록달록한 색깔 띠가 4개 또는 5개 그려져 있습니다. 저항은 너무 작아서 숫자를 인쇄할 수 없기 때문에 이 색깔 띠로 저항 값(Ω)을 표시합니다.

가장 흔한 **4색띠 저항** 읽는 법은 다음과 같습니다.

- **첫 번째 띠:** 십의 자리 숫자
- **두 번째 띠:** 일의 자리 숫자
- **세 번째 띠:** 승수 (10을 몇 번 곱할 것인가 = 뒤에 붙을 0의 개수)
- **네 번째 띠:** 오차 범위 (보통 금색은 플러스 마이너스 5% 오차)

> **💡 자주 쓰는 저항 값 예시 (외워두면 편리합니다)**
>
> - **갈색-검은색-적색 (1 - 0 - 100):** 10 X 100 = 1,000 \\ Omega (1 k\\Omega) ➡️ 대개 스위치나 통신 회로에 많이 씁니다.
> - **적색-적색-갈색 (2 - 2 - 10):** 22 X 10 = 220 \\ Omega ➡️ ATmega128A에서 **LED 켤 때 가장 많이 쓰는 저항**입니다.

<a id="notion-37a1d46c18fc804b83b0d0a9925ff4c0"></a>

## 📌 한 줄 요약

> **"저항은 전기의 수도꼭지다\! 너무 많이 흐르면 부품이 터지니 저항으로 조절하고, 신호가 불안정하면 저항으로 고정한다. 임베디드 회로에서 저항 없는 안전한 회로는 없다."**

# 💡 빛을 내는 반도체: LED (Light Emitting Diode, 발광 다이오드)

> **💡 한 줄 요약:** 전기가 한쪽 방향으로 흐를 때 빛을 내는 \*\*'방향성이 있는 전등(반도체 소자)'\*\*입니다.

<a id="notion-37a1d46c18fc8053b04bd11469c01669"></a>

## 1\. LED의 가장 중요한 특징: 방향성 (극성)

일반적인 백열전구나 저항은 플러스, 마이너스 방향을 반대로 꽂아도 잘 작동합니다. 하지만 **LED는 반드시 극성(+, -)을 맞춰서 꽂아야만 불이 켜집니다.** 반대로 꽂으면 전기가 아예 통하지 않습니다.

- **애노드 (Anode):** **플러스(+) 극**입니다. 다리가 **긴 쪽**입니다. (ATmega128A의 GPIO 핀이나 5V 전원에 연결)
- **캐소드 (Cathode):** **마이너스(-) 극**입니다. 다리가 **짧은 쪽**입니다. (GND에 연결)

> 📌 **실무 팁:** 다리가 이미 잘려 있어서 길이가 똑같다면, LED 플라스틱 몸통 안을 들여다보세요. 칩 모양이 <strong>작은 쪽이 플러스(+)</strong>, 부채꼴 모양으로 \*\*큰 쪽이 마이너스(-)\*\*입니다. 몸통 테두리가 살짝 깎여서 평평한 쪽이 마이너스(-)이기도 합니다.

<a id="notion-37a1d46c18fc80489599f0d6185a0bc0"></a>

## 2\. 회로도 기호와 작동 원리

- **기호:** 삼각형 앞에 선이 막고 있고, 빛이 나간다는 뜻의 **화살표 2개**가 그려진 모양입니다. 삼각형의 넓은 면이 플러스(+), 뾰족한 벽면이 마이너스(-)입니다.
- **순방향 전압 (Forward Voltage):** LED를 켜기 위해 필요한 '최소한의 전압 넘기'입니다. 보통 빨간색 LED는 약 2V, 파란색이나 흰색 LED는 약 3V 이상의 전기가 들어와야 비로소 불이 켜지기 시작합니다.

<a id="notion-37a1d46c18fc80408e68f9d6ce15d8eb"></a>

## 3\. ATmega128A에서 LED를 제어하는 2가지 방법

나중에 C언어로 코드를 짜서 보드의 LED를 켤 때, 회로가 어떻게 구성되어 있느냐에 따라 코딩 방식이 정반대가 됩니다.

<a id="notion-37a1d46c18fc8092a6aee76199021fde"></a>

### ① Sink 방식 (0을 줄 때 켜짐) — *개발 보드에서 많이 씀*

- **구조:** \[5V 전원\] ➡️ \[저항\] ➡️ \[LED\] ➡️ **\[ATmega128A 핀\]** 순서로 연결된 구조입니다.
- **원리:** 전기는 높은 곳(5V)에서 낮은 곳으로 흐릅니다. 핀을 `0(GND, 0V)`으로 만들어주어야 5V에서 출발한 전기가 핀 안으로 쏙 빠져나가면서 LED가 켜집니다.
- **코드:** `PORTA = 0x00;` 하면 LED가 **켜지고**, `PORTA = 0xFF;` 하면 LED가 **꺼집니다.**

<a id="notion-37a1d46c18fc80a49930e9f0eecc4c45"></a>

### ② Source 방식 (1을 줄 때 켜짐)

- **구조:** **\[ATmega128A 핀\]** ➡️ \[저항\] ➡️ \[LED\] ➡️ \[GND\] 순서로 연결된 구조입니다.
- **원리:** 핀에서 직접 전기를 밀어내야 합니다. 핀을 `1(High, 5V)`로 만들어주어야 전기가 LED를 거쳐 GND로 빠져나가며 불이 켜집니다.
- **코드:** `PORTA = 0xFF;` 하면 LED가 **켜지고**, `PORTA = 0x00;` 하면 LED가 **꺼집니다.**

<a id="notion-37a1d46c18fc80599a06f459ad7b4dce"></a>

## 📊 노션 정리용 최종 요약

|  |  |
| --- | --- |
| **항목** | **내용** |
| **긴 다리 / 작은 칩** | 애노드 (Anode) ➡️ **플러스 (+)** |
| **짧은 다리 / 큰 칩** | 캐소드 (Cathode) ➡️ **마이너스 (-)** |
| **필수 짝꿍 부품** | **저항 (보통 220옴 \~ 330옴)** ➡️ 과전류로 LED가 타는 것을 방지 |
