### 1\. 매뉴얼 확인 (`man`)

- **개념**: 명령어, 시스템 콜, 라이브러리 함수 등의 공식 매뉴얼 페이지 확인
- **문법**: `man [섹션번호] <명령어/함수명>`

|  |  |  |
| --- | --- | --- |
| **섹션 번호** | **대상** | **예시** |
| **1** | 사용자 명령어 (User Commands) | `man 1 ls` |
| **2** | 시스템 콜 (System Calls, 커널 호출) | `man 2 open`, `man 2 read` |
| **3** | C 라이브러리 함수 (Library Functions) | `man 3 printf`, `man 3 malloc` |

- **주요 옵션**:

  - `man -k <키워드>`: 해당 키워드가 설명에 포함된 매뉴얼 페이지 목록 검색 (예: `man -k tar`)

> **시험 대비 포인트**
>
> - **주관식/객관식**: 섹션 1(명령어), 2(시스템 콜), 3(C 라이브러리)의 구분 묻는 문제 빈출.
> - 시스템 콜과 라이브러리 함수 이름이 겹칠 때(예: `write`) 원하는 매뉴얼을 보려면 반드시 섹션 번호를 지정해야 함 (`man 2 write`).

### 2\. 명령어 유형 (외부 명령 vs 셸 내장 명령)

|  |  |  |
| --- | --- | --- |
| **구분** | **외부 명령 (External Command)** | **셸 내장 명령 (Shell Built-in)** |
| **정의** | 독립된 바이너리 실행 파일로 디스크에 존재 | 셸(`bash`) 프로세스 자체에 내장된 명령 |
| **위치 확인** | `which <명령어>` (예: `which ls` → `/usr/bin/ls`) | `which`로 검색 불가 또는 외부 대체 경로 출력 |
| **도움말** | `man <명령어>` | `help <명령어>` (예: `help cd`) |
| **대표 예시** | `ls`, `cp`, `mv`, `rm` | `cd`, `type`, `pwd`, `exit` |

- **판별 명령어**: `type <명령어>`

  - `type cp` → `cp is /usr/bin/cp` (외부)
  - `type cd` → `cd is a shell builtin` (내장)
- **우선순위 및 강제 실행**:

  - 외부/내장에 둘 다 존재하는 명령(예: `echo`)을 실행하면 **셸 내장 명령이 우선 실행**됨.
  - 외부 바이너리로 강제 실행하려면 **절대 경로** 입력: `/usr/bin/echo`

### 3\. 디렉터리 탐색 및 관리

**1\) 경로 표기 규칙**

- **절대 경로**: `/`(루트) 또는 `~`(홈 디렉터리)로 시작하는 경로
- **상대 경로**: 현재 작업 디렉터리를 기준으로 시작하는 모든 경로

|  |  |
| --- | --- |
| **기호** | **의미** |
| `~` | 현재 사용자의 홈 디렉터리 (`/home/username`) |
| `.` | 현재 작업 디렉터리 |
| `..` | 상위(부모) 디렉터리 |
| `/` | 파일 시스템 최상위 루트 디렉터리 |
| `-` | 직전 작업 디렉터리 (`cd -`) |

**2\) 디렉터리 이동 및 위치 확인**

- `pwd`: 현재 작업 디렉터리의 절대 경로 출력 (**P**rint **W**orking **D**irectory)
- `cd <경로>`: 작업 디렉터리 이동 (**C**hange **D**irectory)

<strong>3\) 디렉터리 조회 (</strong><strong>`ls`</strong><strong>)</strong>

- `ls -a`: 숨김 파일(`.`으로 시작)을 포함한 모든 파일 출력 (**A**ll)
- `ls -l`: 권한, 소유자, 크기, 수정시간 등 상세 정보 출력 (**L**ong)
- `ls -al <경로>`: 지정 경로 내 모든 파일의 상세 정보 조회 (옵션 조합 가능)

**4\) 디렉터리 생성 및 삭제**

- `mkdir <디렉터리명>`: 새 디렉터리 생성 (**M**a**k**e **Dir**ectory)

  - `mkdir -p a/b/c`: 상위 디렉터리가 없으면 자동 생성 (**P**arents, 에러 무시)
- `rmdir <디렉터리명>`: **비어 있는** 디렉터리만 삭제 (**R**e**m**ove **Dir**ectory)

  - 내부에 파일이나 서브 디렉터리가 있으면 삭제되지 않고 `Directory not empty` 에러 발생.

> **시험 대비 포인트**
>
> - **단답형/객관식**: `rmdir`는 내용물이 있는 디렉터리를 지울 수 없음 (내용물이 있는 폴더 강제 삭제는 `rm -r`).
> - **약어 및 옵션**: `mkdir -p`의 `p`(parents) 기능, `ls -a`의 숨김 파일 기준(`.`).

<a id="notion-3de1d46c18fc80008c54d35a554a3b29"></a>

### 4\. 파일 정보 및 상태 확인 (`file`, `stat`)

- <strong>`file`</strong>: 파일의 종류(텍스트, 바이너리, 실행 파일 등)를 분석하여 출력

  - `file /etc/issue` → `ASCII text` (일반 텍스트 파일)
  - `file /bin/ls` → `ELF 64-bit LSB ...` (리눅스 표준 바이너리 실행 파일 포맷인 ELF)
- <strong>`stat`</strong>: 파일의 상세 상태(크기, 권한, Inode, UID/GID) 및 3대 타임스탬프 출력

|  |  |  |
| --- | --- | --- |
| **타임스탬프 항목** | **전체 이름** | **의미** |
| **Access (atime)** | Access Time | 파일 내용을 마지막으로 읽거나 실행한 시간 |
| **Modify (mtime)** | Modification Time | 파일 \*\*내용(Content)\*\*이 마지막으로 수정된 시간 |
| **Change (ctime)** | Status Change Time | 파일 \*\*메타데이터(속성, 권한, 소유자, 이름 등)\*\*가 변경된 시간 |

### 5\. 파일 생성 및 조작 (`touch`, `cp`, `mv`, `rm`)

<strong>1\) 빈 파일 생성 및 시간 갱신 (</strong><strong>`touch`</strong><strong>)</strong>

- `touch <파일명>`

  - 파일이 **없으면**: 크기가 0인 빈 파일 생성
  - 파일이 **이미 있으면**: 파일 내용은 유지한 채 타임스탬프(atime, mtime)를 현재 시간으로 갱신

<strong>2\) 파일 및 디렉터리 복사 (</strong><strong>`cp`</strong><strong>)</strong>

- **기본 문법**: `cp [옵션] <원본> <대상>`
- **복수 파일 복사**: `cp file1 file2 dir/` (여러 파일을 특정 디렉터리로 한 번에 복사)

|  |  |  |
| --- | --- | --- |
| **옵션** | **명칭 / 의미** | **동작 상세** |
| **`-i`** | Interactive | 대상 파일이 이미 존재하면 덮어쓸지 여부를 사용자에게 확인 (`y/n`) |
| **`-f`** | Force | 대상 파일이 존재하나 열기(쓰기)가 불가능할 때, **기존 파일을 강제로 삭제한 후 새로 복사 시도** |
| **`-r`** <strong>(또는</strong> <strong>`-R`</strong><strong>)</strong> | Recursive | 하위 디렉터리 및 내부 파일을 포함하여 디렉터리를 재귀적으로 통째 복사 |

<strong>3\) 파일 및 디렉터리 이동 / 이름 변경 (</strong><strong>`mv`</strong><strong>)</strong>

- **기본 문법**: `mv [옵션] <원본> <대상>`

  - 대상이 **존재하지 않는 이름**: 이름 변경 (Rename, 예: `mv hello.c hello_1.c`)
  - 대상이 **이미 존재하는 디렉터리**: 디렉터리 내부로 이동 (Move, 예: `mv hello_1.c MyDir/`)
  - `mv MyDir MyDir_2`: `MyDir_2`가 없으면 폴더명 변경, 이미 있으면 `MyDir_2` 내부로 `MyDir` 폴더 통째 이동
- **주요 옵션**: `f` (강제 덮어쓰기, 질의 없이 즉시 실행)

<strong>4\) 파일 및 디렉터리 삭제 (</strong><strong>`rm`</strong><strong>)</strong>

- **기본 문법**: `rm [옵션] <대상>`

  - `rm hello.c`: 일반 파일 단일 삭제
- **주요 옵션**:

  - **`r`** <strong>(Recursive)</strong>: 디렉터리 및 그 안의 모든 내용물 삭제
  - **`f`** <strong>(Force)</strong>: 삭제 대상 파일이 없어도 에러 메시지를 띄우지 않고 통과 (경고창/확인 절차 무시)

<a id="notion-3de1d46c18fc80cfbe48cecd05c78413"></a>

### 6\. 링크 파일 생성 (`ln`)

- **개념**: 기존 파일이나 디렉터리를 가리키는 링크(바로가기 개념) 생성
- **문법**: `ln -s <원본경로> <링크파일명>`

  - `ln -s /etc/issue myissue`: `/etc/issue`를 가리키는 심볼릭 링크 `myissue` 생성
  - `ln -s /etc myetc`: 디렉터리 대상 심볼릭 링크 생성도 가능

|  |  |  |  |
| --- | --- | --- | --- |
| **링크 종류** | **명령어 형식** | **파일 유형 표기 (ls -l)** | **특징** |
| **심볼릭 링크 (Symbolic/Soft)** | `ln -s <원본> <링크>` | 맨 앞 글자 **`l`** (예: `lrwxrwxrwx`) | • 원본의 경로 포인터를 저장 (바로가기)<br><br>• 원본 삭제 시 링크가 깨짐<br><br>• 디렉터리 링크 가능, 다른 파일시스템 가능 |
| **하드 링크 (Hard)** | `ln <원본> <링크>` | 일반 파일 **`-`** | • 원본과 동일한 Inode 공유<br><br>• 원본 파일명이 지워져도 데이터 유지<br><br>• 디렉터리 링크 불가 |

> **시험 대비 핵심 체크 (★ 단골 출제)**
>
> - <strong>`cp -f`</strong>**의 정확한 의미**: 단순 덮어쓰기가 아니라, 대상 파일이 권한 문제 등으로 열리지 않을 때 **강제로 삭제(unlink) 후 재생성**하여 복사한다는 점.
> - <strong>`touch`</strong>**의 이중 용도**: 빈 파일 생성뿐만 아니라 **기존 파일의 타임스탬프를 현재 시각으로 갱신**하는 기능.
> - **`stat`** <strong>타임스탬프 구분</strong>:
>
>   - `Modify(mtime)`: 파일의 **내용** 수정.
>   - `Change(ctime)`: 파일의 **권한, 소유자, 크기 등 메타데이터** 변경. (mtime 변경 시 ctime도 보통 함께 변경됨)
> - **`ln -s`** <strong>심볼릭 링크 식별</strong>: `ls -l` 실행 시 파일 속성 맨 첫 자리가 `l`로 표기되며 `>` 화살표로 원본을 가리킴.

### 7\. 텍스트 파일 내용 확인 (`cat`, `more`, `less`, `head`, `tail`)

- **개념**: 텍스트 파일의 전체 또는 일부 내용을 터미널 화면에 출력

|  |  |
| --- | --- |
| **명령어** | **주요 특징 및 동작 방식** |
| **`cat`** | 파일 전체 내용을 한 번에 터미널로 쏟아내듯 출력 (파일이 길면 화면이 위로 스크롤되어 지나감) |
| **`more`** | 파일 내용을 화면(페이지) 단위로 끊어서 출력. **스페이스바**(다음 페이지), **Enter**(한 줄씩 아래로), `q`(종료). 역방향(위로) 이동이 제한적임 |
| **`less`** | `more`의 확장 개선형. \*\*위/아래 방향키(또는 j/k)\*\*로 자유롭게 상/하 스크롤 가능. 앞/뒤 검색 기능 지원 |
| **`head`** | 파일의 \*\*시작(앞부분)\*\*부터 지정한 줄 수만큼 출력 |
| **`tail`** | 파일의 \*\*끝(마지막)\*\*부터 지정한 줄 수만큼 출력 |

- **문법 및 옵션**:

  - 기본 출력 줄 수: 옵션 미지정 시 **기본 10줄** 출력
  - 줄 수 지정: `head -5 /etc/profile` 또는 `head -n 5 /etc/profile` (동일 동작)
  - `tail -20 /etc/profile` (끝에서부터 20줄 출력)
  - `tail -f <파일명>`: 파일 끝에 새로 추가되는 내용을 실시간 모니터링 (**F**ollow, 로그 파일 분석 시 필수)

### 8\. 사용자와 그룹 및 계정 관리 파일

리눅스는 여러 사용자가 동시에 접근하는 **다중 사용자(Multi-User)** 시스템이므로 계정과 그룹 권한을 파일로 분리하여 관리합니다.

**1\) 핵심 설정 파일 4가지**

|  |  |  |
| --- | --- | --- |
| **파일 경로** | **관리 내용** | **권한 및 특징** |
| **`/etc/passwd`** | 사용자 계정의 기본 정보 (계정명, UID, 기본 GID, 홈 디렉터리, 기본 셸) | 모든 사용자가 읽기 가능 (`-rw-r--r--`) |
| **`/etc/shadow`** | 사용자의 **단방향 암호화된 비밀번호** 및 비밀번호 만료 주기 | root 관리자만 읽기 가능 (`-rw-r-----` 또는 `-r--------`) |
| **`/etc/group`** | 시스템의 그룹 정보 (그룹명, GID, 해당 그룹을 보조 그룹으로 둔 사용자 목록) | 모든 사용자가 읽기 가능 (`-rw-r--r--`) |
| **`/etc/gshadow`** | 그룹의 암호화된 비밀번호 및 그룹 관리자 정보 | root 관리자만 접근 가능 |

**2\) 사용자/그룹 필드 구조와 GID 분석 (★ 시험 핵심 포인트)**

- **`/etc/passwd`** <strong>한 줄 구조</strong>:

  ```text
  user1:x:1001:1001:Developer:/home/user1:/bin/bash
  [계정명]:[비번]:[UID]:[주 그룹 GID]:[설명]:[홈디렉터리]:[로그인셸]
  ```
- **`/etc/group`** <strong>한 줄 구조</strong>:

  ```text
  project:x:1002:user1,user2,user3
  [그룹명]:[그룹비번]:[GID]:[보조 그룹으로 사용하는 사용자들(쉼표 구분)]
  ```

> **교수님 강조\! 헷갈리는 GID 시험 포인트 (주 그룹 vs 보조 그룹)**
>
> - <strong>사용자의 주 그룹(Primary Group / 기본 그룹)</strong>:
>
>   - 사용자가 파일을 새로 생성했을 때 기본적으로 할당되는 소유 그룹.
>   - 사용자의 주 그룹 GID는 **/etc/passwd의 4번째 필드**에 명시됨.
>   - **주의**: 사용자의 주 그룹은 `/etc/group` 맨 끝 사용자 리스트에 **적히지 않아도** 이미 주 그룹으로 소속되어 있음\!
> - <strong>사용자의 보조 그룹(Secondary / Supplementary Group)</strong>:
>
>   - 기본 그룹 외에 추가 권한을 주기 위해 사용자를 등록하는 그룹.
>   - `/etc/group`의 맨 마지막 필드에 사용자 이름이 콤마(`,`)로 명시되어 있는 경우, 그 사용자는 해당 그룹을 **보조 그룹**으로 가짐.

<a id="notion-3de1d46c18fc802db4c8d5e0b1307c39"></a>

### 9\. 파일 접근 권한 및 종류 (File Permissions)

`ls -l` 출력 결과의 첫 10자리는 파일 유형(1글자)과 권한(9글자)을 나타냅니다.

```text
-  rw-  r--  ---  1  syslog  adm  2262359  Sep 17 14:17  /var/log/syslog
[1] [ 2 ] [ 3 ] [ 4 ]
```

- **`[1]`** <strong>파일 종류 (1자리)</strong>
- **`[2]`** <strong>소유자(User) 권한 (3자리)</strong>: `rw-`
- **`[3]`** <strong>소유 그룹(Group) 권한 (3자리)</strong>: `r--`
- **`[4]`** <strong>기타 사용자(Other) 권한 (3자리)</strong>: `--`

**1\) 파일 종류 문자 (Type, 1자리)**

|  |  |  |
| --- | --- | --- |
| **문자** | **파일 종류** | **설명** |
| **`-`** | 정규 파일 (Regular File) | 일반 텍스트, 바이너리 실행 파일, 이미지, 압축 파일 등 |
| **`d`** | 디렉터리 (Directory) | 폴더 |
| **`l`** | 심볼릭 링크 (Symbolic Link) | 바로가기 링크 파일 |
| **`c`** | 문자 디바이스 (Character Device) | 글자(바이트) 단위 입출력 장치 (예: 키보드, UART 콘솔 `/dev/tty*`) |
| **`b`** | 블록 디바이스 (Block Device) | 블록 단위(섹터) 입출력 저장 장치 (예: 하드디스크, SSD `/dev/sda`, `/dev/nvme*`) |
| **`p`** | 파이프 (Named Pipe / FIFO) | 프로세스 간 통신(IPC) 통로 |
| **`s`** | 소켓 (Socket) | 네트워크 또는 로컬 프로세스 간 IPC 소켓 |

**2\) 기본 접근 권한 (Permissions, 9자리)**

|  |  |  |  |
| --- | --- | --- | --- |
| **권한** | **의미** | **일반 파일(File)에서의 의미** | **디렉터리(Directory)에서의 의미** |
| **`r`** | Read | 파일 내용 읽기/조회 | 디렉터리 내부 파일 목록 조회 가능 (`ls`) |
| **`w`** | Write | 파일 내용 수정/추가/삭제 | 디렉터리 내부에서 파일 생성/이름변경/삭제 가능 |
| **`x`** | Execute | 파일을 프로그램/스크립트로 실행 | 디렉터리로 <strong>이동/접근 가능 (</strong><strong>`cd`</strong><strong>) 및 파일 메타정보 접근</strong> |

> **필기 내용 정정 및 시험 대비 주의점**
>
> - **일반 파일**: 필기 메모 중 "r, w가 있어도 x가 없으면 무의미"는 **디렉터리에 해당하는 규칙**입니다. 일반 파일은 `x`가 없어도 `r`만 있으면 문서 편집기로 정상적으로 읽을 수 있고, `w`만 있으면 수정할 수 있습니다. (바이너리/스크립트 실행만 안 됨)
> - <strong>디렉터리에서의</strong> **`x`** <strong>(단골 문제)</strong>:
>
>   - 디렉터리는 <strong>`x`</strong><strong>(실행 권한)가 있어야만</strong> **`cd`** <strong>명령으로 진입</strong>할 수 있습니다.
>   - 디렉터리에 `r`만 있고 `x`가 없으면: 파일 목록 이름(`ls`)은 겨우 보이지만, 그 디렉터리로 들어갈 수 없으며(`cd 불가`), 내부 파일의 상세 정보(`stat`, `ls -l` 등)나 내용을 열 수 없습니다.

### 10\. 파일 접근 권한 변경 (`chmod`)

- **개념**: 기존 파일이나 디렉터리의 읽기(`r`), 쓰기(`w`), 실행(`x`) 접근 권한을 변경
- **권한 제약**: 해당 파일의 **소유자(Owner)** 또는 최고 관리자(root)만 실행 가능

**1\) 8진수 모드 (Octal Mode)**

- 3비트 2진수 체계를 8진수 숫자로 변환하여 전체 권한(소유자, 그룹, 기타 사용자)을 한 번에 설정

|  |  |  |  |
| --- | --- | --- | --- |
| **권한 기호** | **2진수 값** | **8진수 값** | **설명** |
| `r` (Read) | $2^2$ (`100`) | **4** | 읽기 권한 |
| `w` (Write) | $2^1$ (`010`) | **2** | 쓰기 권한 |
| `x` (Execute) | $2^0$ (`001`) | **1** | 실행 권한 |
| `-` (None) | `000` | **0** | 권한 없음 |

- **조합 계산 예시**:

  - `rwx` = $4 + 2 + 1 = \mathbf{7}$
  - `rw-` = $4 + 2 + 0 = \mathbf{6}$
  - `r-x` = $4 + 0 + 1 = \mathbf{5}$
  - `r--` = $4 + 0 + 0 = \mathbf{4}$
- **사용 예시**: `chmod 764 hello.c` → `rwx`(7) `rw-`(6) `r--`(4)

**2\) 기호 모드 (Symbolic Mode)**

- 대상, 연산자, 권한 기호를 조합하여 특정 권한만 선택적으로 추가/제거

|  |  |  |
| --- | --- | --- |
| **대상 (Who)** | **연산자 (Op)** | **권한 (Permission)** |
| **`u`** : 소유자 (User)<br><br>**`g`** : 소유 그룹 (Group)<br><br>**`o`** : 기타 사용자 (Other)<br><br>**`a`** : 모든 사용자 (All, `u+g+o`) | **`+`** (추가)<br><br>**`-`** (제거)<br><br>**`=`** (동일하게 지정) | **`r`** : 읽기<br><br>**`w`** : 쓰기<br><br>**`x`** : 실행 |

- **동작 변환 예시**:

  - `chmod a-x hello.c`: 모든 사용자(`a`)에게서 실행 권한(`x`) 제거 (`764` → `664`)
  - `chmod o+w hello.c`: 기타 사용자(`o`)에게 쓰기 권한(`w`) 추가 (`664` → `666`)
  - `chmod ug+x,o-r hello.c`: 콤마(`,`)로 여러 조건 동시 부여 가능

<a id="notion-3de1d46c18fc80e39dddd7b819985ced"></a>

### 11\. 파일 소유권 및 그룹 변경 (`chown`, `chgrp`)

- **권한 제약**: 파일의 소유자를 변경하는 작업은 보안상 **root 관리자**만 수행 가능

|  |  |  |
| --- | --- | --- |
| **명령어** | **형식** | **설명** |
| **`chown`** | `chown [옵션] <소유자> <파일/폴더>` | 파일의 소유자 변경 (예: `sudo chown root hello.c`) |
|  | `chown [옵션] <소유자>:<그룹> <파일/폴더>` | 소유자와 소유 그룹을 **동시에 변경** (예: `sudo chown aidl:root hello.c`) |
| **`chgrp`** | `chgrp [옵션] <그룹> <파일/폴더>` | 소유 그룹만 변경 (예: `sudo chgrp aidl hello.c`) |

- **주요 옵션**: `R` (Recursive) → 디렉터리 하위의 모든 파일과 폴더의 소유권을 일괄 변경

<a id="notion-3de1d46c18fc80be8bd9c4631186833b"></a>

### 12\. 기본 권한 마스크 (`umask`)

- **개념**: 사용자가 파일이나 디렉터리를 새로 생성할 때 부여할 **최대 기본 권한에서 특정 권한을 차단(Masking)하는 값**
- **목적**: 실수로 보안상 위험한 권한(예: 일반 실행 권한, 타인의 쓰기 권한)이 기본 활성화되는 것을 방지
- **출력**: `umask` 입력 시 보통 `0002` 또는 `0022` 4자리 출력

  - 맨 앞의 `0`: 특수 권한(SetUID/SetGID/Sticky bit) 자리이며 일반 umask 계산 시 무시
  - 뒤 3자리: 각각 <strong>소유자(u)</strong>, <strong>소유 그룹(g)</strong>, 기타 사용자(o)에서 제거할 비트

**1\) 파일 vs 디렉터리 생성 권한 계산 (★ 주관식/계산 문제 1순위)**

- 시스템이 부여하는 <strong>최초 최대 권한 (Max Permission)</strong>:

  - **일반 파일**: **`666`** (`rw-rw-rw-`) → 일반 파일은 생성 시 기본적으로 실행(`x`) 권한을 주지 않음
  - **디렉터리**: **`777`** (`rwxrwxrwx`) → 디렉터리는 탐색 및 접근(`cd`)을 위해 실행(`x`) 권한이 필수임
- **최종 권한 계산 원리**: `최대 권한 & ~umask` (비트 AND-NOT 연산, 겹치는 권한 비트를 박탈)

|  |  |  |  |
| --- | --- | --- | --- |
| **구분** | **최초 최대 권한** | **umask 022 적용 시** | **umask 002 적용 시** |
| **디렉터리** | `777` (`rwxrwxrwx`) | **`755`** (`rwxr-xr-x`) | **`775`** (`rwxrwxr-x`) |
| **일반 파일** | `666` (`rw-rw-rw-`) | **`644`** (`rw-r--r--`) | **`664`** (`rw-rw-r--`) |

- **umask 변경**: `umask 002` 또는 `umask 022` 명령으로 현재 셸 세션의 마스크 값 즉시 변경 가능

> **시험 대비 핵심 체크 (★ 단골 출제)**
>
> - **8진수 ↔ 기호 모드 상호 변환**:
>
>   - `chmod 640 file`을 기호 모드로 풀면? `u=rw,g=r,o=`
>   - `rw-r--r--` 상태에서 `chmod g+w,o-r` 적용 시 8진수 값은? `660`
> - **소유권 변경 명령어 차이**:
>
>   - `chown`은 소유자와 그룹을 한 번에 바꿀 수 있음 (`chown user:group file`).
>   - `chgrp`는 그룹만 바꿀 수 있음.
> - **`umask`** <strong>계산 함정 주의</strong>:
>
>   - 파일의 최대 권한은 `777`이 아닌 \*\*`666`\*에서 시작함.
>   - 만약 umask가 `027`이라면?
>
>     - 디렉터리: $777 - 027 = \mathbf{750}$ (`rwxr-x---`)
>     - 일반 파일: $666$에서 그룹의 `w(2)` 제거, others의 `rwx(7)` 제거 → **`640`** (`rw-r-----`)
>     - <em>(단순 뺄셈</em> *$666 - 027 = 639$* <em>같은 연산 오류를 범하지 않도록 비트 제거 개념 숙지 필수)</em>

### 13\. 텍스트 패턴 검색 (`grep`)

- **개념**: 파일 내부나 입력 스트림에서 지정한 정규표현식/문자열 패턴과 일치하는 행을 검색하여 출력
- **문법**: `grep [옵션] <패턴> [대상파일...]`

  - 예시: `grep root /etc/passwd` -&gt; `/etc/passwd` 파일에서 `root` 문자열이 포함된 모든 행 출력

|  |  |  |
| --- | --- | --- |
| **옵션** | **명칭 / 기능** | **상세 설명** |
| **`-v`** | Invert Match | 패턴을 **포함하지 않는** 행만 반전하여 출력 |
| **`-i`** | Ignore Case | 영문의 대소문자 구분을 무시하고 검색 |
| **`-w`** | Word Regexp | 패턴이 독립된 완전한 \*\*단어(Word)\*\*로 일치하는 경우만 검색 (예: `root` 검색 시 `rootfs`, `chroot` 제외) |
| **`-c`** | Count | 매칭된 행의 내용을 출력하지 않고, **일치한 행의 총 개수**만 출력 |
| **`-n`** | Line Number | 파일 내에서 일치한 행의 **줄 번호**를 함께 출력 |
| **`-r`** <strong>(또는</strong> <strong>`-R`</strong><strong>)</strong> | Recursive | 지정한 디렉터리 및 하위 디렉터리 내의 모든 파일을 재귀적으로 검색 |
| **`-rn`** | Recursive + Number | 하위 디렉터리 전체를 뒤져 일치하는 파일명, 줄 번호, 내용을 동시 출력 (실무/디버깅 빈출) |

### 14\. ★ 표준 입출력(Standard I/O)과 리다이렉션(Redirection)

리눅스 프로세스는 파일 디스크립터(FD, File Descriptor) 번호 `0`, `1`, `2`를 통해 외부와 데이터를 주고받습니다. 자식 프로세스는 부모 프로세스(보통 셸)의 파일 디스크립터 테이블을 기본적으로 상속받습니다.

**1\) 표준 스트림 종류 (FD)**

|  |  |  |  |
| --- | --- | --- | --- |
| **FD 번호** | **명칭** | **기본 장치** | **설명** |
| **`0`** | **표준 입력 (stdin)** | 키보드 | 프로그램으로 들어가는 입력 데이터 스트림 |
| **`1`** | **표준 출력 (stdout)** | 모니터(터미널) | 프로그램의 정상 실행 결과 출력 스트림 |
| **`2`** | **표준 에러 (stderr)** | 모니터(터미널) | 프로그램 실행 중 발생하는 에러 메시지 스트림 |

**2\) 리다이렉션 연산자 (Redirection)**

표준 입출력의 방향을 모니터나 키보드가 아닌 **파일**로 재지정합니다.

|  |  |  |
| --- | --- | --- |
| **연산자** | **대상 스트림** | **동작 설명 및 예시** |
| **`>`** | 표준 출력 (`1>`) | 파일에 출력 결과를 **덮어쓰기(Overwrite)** (`ls -l > list.txt`) |
| **`>>`** | 표준 출력 (`1>>`) | 기존 파일 내용 끝에 결과를 **이어쓰기(Append)** (`echo "fail" >> log.txt`) |
| **`<`** | 표준 입력 (`0<`) | 키보드 대신 파일의 내용을 입력으로 전달 (`cat < list.txt`) |
| **`2>`** | 표준 에러 | 에러 메시지만 지정한 파일로 분리 저장 (`grep conf /etc/* 2> error.log`) |
| **`2>>`** | 표준 에러 | 에러 메시지를 지정한 파일 끝에 이어쓰기 |

**3\) 표준 출력과 표준 에러의 동시 리다이렉션**

- **`> all.txt 2>&1`** <strong>(표준/전통적 방식)</strong>:

  - `2>&1`: 2번(stderr)을 1번(stdout)이 현재 가리키고 있는 곳(`all.txt`)으로 결합 출력
  - 주의: 반드시 `> all.txt` 뒤에 `2>&1`을 적어야 정상 동작
- **`&> all.txt`** <strong>(Bash 확장 문법)</strong>:

  - 표준 출력과 표준 에러를 한 번에 `all.txt`로 덮어쓰기 (`&>> all.txt`는 이어쓰기)

<a id="notion-3de1d46c18fc80a3bdfde05c7a79f199"></a>

### 15\. 파이프 (Pipe, `|`)

- **개념**: 앞 명령어의 표준 출력(stdout)을 뒤 명령어의 표준 입력(stdin)으로 직접 연결하는 통로 (프로세스 간 단방향 IPC)
- **동작 흐름**: `[명령어 A] --(stdout)--> | --(stdin)--> [명령어 B]`

**1\) 주요 파이프 조합 패턴**

- `ls -l /etc | grep conf`: `/etc` 폴더 목록 중 `conf`가 포함된 줄만 필터링
- `ls -l /etc | grep conf | less`: 필터링된 방대한 결과를 `less` 페이저로 상/하 스크롤하며 확인
- `cat /etc/passwd | grep sys`: `/etc/passwd` 내용을 `grep`의 표준 입력으로 전달하여 `sys` 검색 <em>(참고:</em> <em>`grep sys /etc/passwd`</em>*와 동일하지만 파이프 연계 학습용으로 자주 사용)*
- `dmesg | grep -i error`: 커널 부팅/동작 로그 중 대소문자 구분 없이 에러 로그만 선별

> **시험 대비 핵심 체크 (★ 단골 출제)**
>
> - **`>`** <strong>vs</strong> **`>>`** <strong>차이 (단답형)</strong>:
>
>   - `>`는 파일이 이미 존재할 경우 <strong>기존 내용을 완전히 지우고 덮어씀(Truncate/Overwrite)</strong>.
>   - `>>`는 기존 내용을 보존하고 <strong>맨 마지막 줄 뒤에 덧붙임(Append)</strong>.
> - <strong>파일 디스크립터 번호 매핑 (객관식)</strong>:
>
>   - `0`: stdin, `1`: stdout, `2`: stderr.
>   - 숫자 생략 시 `>`는 `1>`로 간주되고, `<`는 `0<`로 간주됨.
> - <strong>`2>&1`</strong><strong>의 의미 서술 (주관식 단골)</strong>:
>
>   - "표준 에러(2)를 표준 출력(1)이 출력되는 대상(파일 또는 터미널)과 동일한 곳으로 재지정한다"는 의미.
> - **`grep -v`** <strong>vs</strong> **`grep -w`** <strong>(선다형)</strong>:
>
>   - `v`: 지정 패턴을 **제외**한 나머지 행 출력.
>   - `w`: 부분 문자열 매칭이 아닌 **온전한 단어** 단위 매칭.

### 핵심 키워드 총정리 (Core Keywords)

- **매뉴얼 &amp; 명령 유형**: `man 1`(명령어), `man 2`(시스템 콜), `man 3`(C 라이브러리), `man -k`, 외부 명령(`which`), 셸 내장 명령(`help`), `type`
- **디렉터리 &amp; 파일 조작**: `pwd`, `cd -`, `mkdir -p`(Parents), `rmdir`(빈 디렉터리만), `touch`(빈 파일 생성 및 타임스탬프 갱신), `cp -f`(강제 언링크 후 복사), `cp -r`, `mv`, `rm -rf`, `ln -s`(심볼릭 링크, `l`), 하드 링크(동일 Inode 공유)
- **파일 정보 &amp; 타임스탬프**: `file`(ELF, ASCII 판별), `stat`, `atime`(접근), `mtime`(내용 수정), `ctime`(속성/메타데이터 변경)
- **계정 &amp; 권한 관리**: `/etc/passwd`(UID, 주 그룹 GID), `/etc/shadow`(단방향 암호화 비번), `/etc/group`(보조 그룹 명시), `chmod`(8진수 4:2:1 / 기호 `u,g,o,a` `+,-,=`), `chown`(소유자:소유그룹 동시 변경), `chgrp`
- **`umask`** <strong>연산</strong>: 최초 최대 권한(디렉터리 `777`, 일반 파일 `666`) → `최대 권한 & ~umask` 연산 (파일 생성 시 실행 권한 `x` 기본 박탈)
- **텍스트 처리 &amp; 검색**: `cat`, `more`, `less`, `head -n`, `tail -f`(실시간 로그 추적), `grep -v`(반전), `grep -i`(대소문자 무시), `grep -w`(단어 일치), `grep -rn`(줄 번호 및 하위 경로 검색)

### ★ 시험 직전 필수 암기 &amp; 감점 방지 가이드

**1\. \[출제 1순위\] 표준 입출력, 리다이렉션 &amp; 파이프**

- **파일 디스크립터(FD) 매핑**: `0 = stdin`(키보드), `1 = stdout`(모니터), `2 = stderr`(모니터)
- **리다이렉션 기호 구분**:

  - `>` : 표준 출력 덮어쓰기 (Truncate/Overwrite)
  - `>>` : 표준 출력 이어쓰기 (Append)
  - `<` : 표준 입력 재지정
  - `2>` : 표준 에러만 분리 저장
  - `> file 2>&1` 또는 `&> file` : 표준 출력과 표준 에러를 동일한 파일로 병합 출력
- <strong>파이프(</strong><strong>`|`</strong><strong>) 동작 원리</strong>:

  - 프로세스 간 단방향 통신(IPC) 통로
  - 앞 명령의 stdout(1) -&gt; 뒤 명령의 stdin(0)으로 전달

<strong>2\. \[수필/주관식 감점 주의\]</strong> **`ls`** <strong>및</strong> **`cat`** <strong>사용 시 주의점</strong>

- **`ls -ld`** <strong>vs</strong> **`ls -l`** <strong>(디렉터리 권한 확인 문제)</strong>:

  - 특정 디렉터리 **자체**의 권한/소유자를 확인하거나 서술할 때 `ls -l <디렉터리>`를 적으면 오답 처리됨 (`ls -l`은 폴더 '내부' 파일 목록을 출력함).
  - 반드시 `d` 옵션을 포함하여 `ls -ld <디렉터리>`로 작성해야 디렉터리 자체의 메타정보를 확인하는 정답으로 인정됨.
- <strong>Useless Use of</strong> **`cat`** <strong>(불필요한 파이프 연계 감점)</strong>:

  - 파일 내용을 검색하거나 처리할 때 습관적으로 `cat file.txt | grep pattern`으로 작성하면 코드 수필 평가 시 불필요한 프로세스 낭비로 감점될 수 있음.
  - 단일 파일 검색은 파일 인자를 직접 받는 **`grep pattern file.txt`** 형태가 가장 표준적인 정답임.
- <strong>디렉터리 대상</strong> **`cat`** <strong>실행 금지</strong>:

  - 디렉터리는 파일 목록을 담는 특수 파일이므로 `cat <디렉터리명>` 사용 시 `Is a directory` 에러 발생 -&gt; 디렉터리 목록 조회는 반드시 `ls` 계열 명령 사용.
- <strong>대용량 파일/로그 확인 시</strong> **`cat`** <strong>남용 주의</strong>:

  - 시스템 로그(`/var/log/*`)나 대용량 커널 출력 확인 시 `cat`을 쓰면 화면 스크롤이 넘어가 확인이 불가능하므로, 문제 의도에 따라 `less`, `head`, `tail -f`를 적재적소에 작성해야 함.
