# Linux 저수준 파일 입출력

## 저수준 파일 입출력 (Low-level File I/O)

### 개념

Linux의 저수준 파일 입출력은 주로 다음 함수를 사용한다.

```plain text
open()
close()
read()
write()
```

이 함수들은 userspace 프로그램에서 사용하며, 실제 파일 처리는 system call을 통해 kernel이 수행한다.

```plain text
User Space
   │
   │ open(), read(), write(), close()
   ▼
System Call Interface
   │
   ▼
Kernel
   │
   ├─ VFS / File System
   ├─ Device Driver
   │
   ▼
Hardware / Storage Device
```

> 정확히는 open(), read() 등은 보통 libc wrapper function이고, 내부에서 해당 system call을 호출한다.

파일을 열면 프로세스는 파일 자체를 직접 다루는 대신 File Descriptor(FD) 라는 정수 값을 사용한다.

---

## Kernel의 역할

Linux에서 kernel은 다음과 같은 핵심 자원을 관리한다.

```plain text
Process
Memory
File
Device
CPU Scheduling
Interrupt
```

따라서 파일 입출력 역시 프로세스가 하드웨어를 직접 제어하는 것이 아니라 kernel을 거친다.

```plain text
User Process
    ↓
System Call
    ↓
Kernel
    ↓
File System / Device Driver
    ↓
Hardware
```

# File Descriptor (FD)

## 개념

File Descriptor는 프로세스가 열린 파일을 식별하기 위해 사용하는 int형 번호이다.

```plain text
int fd;

fd = open("a.txt", O_RDWR);
```

예:

```plain text
fd = 3
```

프로세스 내부에는 FD를 관리하는 테이블이 존재한다.

개념적으로:

```plain text
Process
 │
 └─ File Descriptor Table
      │
      ├─ 0 → stdin
      ├─ 1 → stdout
      ├─ 2 → stderr
      ├─ 3 → a.txt
      └─ 4 → device
```

---

# 표준 File Descriptor

Linux process가 일반적으로 시작할 때 다음 FD가 열려 있다.

| FD | 이름 | 의미 |
|---|---|---|
| 0 | stdin | 표준 입력 |
| 1 | stdout | 표준 출력 |
| 2 | stderr | 표준 에러 |

하지만 FD가 반드시 특정 장치를 의미하는 것은 아니다.

예:

```plain text
./main > output.txt
```

이 경우:

```plain text
fd 1 (stdout)
   ↓
output.txt
```

로 redirect된다.

따라서:

> 0, 1, 2는 표준 입출력의 번호이고, 실제 연결 대상은 상황에 따라 달라질 수 있다.

# Linux의 "Everything is a File" 개념

Linux에서는 일반 파일뿐 아니라 다양한 kernel object를 FD를 이용해 접근한다.

예:

```plain text
Regular File
Device File
Pipe
Socket
Terminal
```

따라서:

```c
read(fd, ...);
write(fd, ...);
```

같은 공통 interface를 사용할 수 있다.

Device Driver를 공부할 때 매우 중요한 개념이다.

```plain text
User Application
      │
   read(fd)
      │
      ▼
System Call
      │
      ▼
Kernel
      │
      ▼
Device Driver
      │
      ▼
Hardware
```

# open()

함수 원형:

```plain text
int open(const char *pathname, int flags);
```

또는

```plain text
int open(const char *pathname, int flags, mode_t mode);
```

성공:

```plain text
File Descriptor 반환
```

실패:

```plain text
-1 반환
errno 설정
```

---

## pathname

파일 경로.

절대 경로:

```plain text
open("/home/user/a.txt", O_RDONLY);
```

상대 경로:

```plain text
open("./a.txt", O_RDONLY);
```

둘 다 가능하다.

---

# open() flags

파일의 open 방식 지정.

Access Mode는 하나를 지정한다.

```plain text
O_RDONLY
O_WRONLY
O_RDWR
```

추가 flag는 bitwise OR로 조합할 수 있다.

```plain text
O_WRONLY | O_CREAT | O_EXCL
```

---

## O_CREAT

파일이 존재하지 않으면 새 파일 생성.

```plain text
open("a.txt",
     O_WRONLY | O_CREAT,
     S_IRUSR | S_IWUSR);
```

### 오타 주의

```plain text
O_CREATE  ❌
O_CREAT   ✅
```

---

## O_EXCL

보통 O_CREAT와 함께 사용한다.

```plain text
O_CREAT | O_EXCL
```

의미:

```plain text
파일 없음
→ 생성

파일 존재
→ open() 실패
```

기존 파일을 실수로 덮어쓰는 것을 막을 수 있다.

# O_NONBLOCK

```plain text
O_NONBLOCK
```

I/O operation에서 non-blocking 동작을 요청한다.

예를 들어 device나 pipe에서 당장 읽을 데이터가 없다면 blocking I/O는 기다릴 수 있다.

```plain text
Blocking

read()
  ↓
데이터 없음
  ↓
Process Sleep
  ↓
데이터 도착
  ↓
Wake-up
```

Non-blocking에서는 보통:

```plain text
read()
  ↓
데이터 없음
  ↓
즉시 error 반환
```

대표적으로:

```plain text
errno = EAGAIN
```

또는

```plain text
EWOULDBLOCK
```

### 수정할 부분

필기의

```plain text
blocking = sleep 가능
nonblocking = sleep 불가능
```
