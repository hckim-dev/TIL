# 디바이스 트리(Device Tree)

<a id="notion-3ed1d46c18fc8050b0c3fa0b79d0d2f2"></a>

## 디바이스 트리(DT)

Device Tree(DT)는 **Board의 Hardware 구성을 Kernel에 알려주는 데이터 구조**이다.

```text
Hardware 정보
↓
DTS
↓ DTC Compile
DTB
↓
Bootloader
↓
Kernel
```

- **DTS(Device Tree Source)** → 사람이 작성하는 Text 형태
- **DTB(Device Tree Blob)** → DTS를 Compile한 Binary
- **DTC(Device Tree Compiler)** → DTS를 DTB로 Compile하는 도구
- Bootloader가 DTB를 Kernel에 전달
- Hardware 정보와 Kernel Code를 분리할 수 있어 **동일 Kernel을 여러 Board에서 활용하기 쉬움**

---

<a id="notion-3ed1d46c18fc80228c60e47aae11cd7e"></a>

## DT 기본 구조

DT는 크게:

```text
Node
+
Property
```

로 구성된다.

<a id="notion-3ed1d46c18fc8078b629e556afe15a36"></a>

### Node

```text
node-name {
    ...
};
```

- 최상위 Node → `/` **Root Node**
- Node 안에 Property와 Child Node가 존재
- Node의 계층 구조는 Hardware의 연결 관계를 표현

Node 이름:

```text
<name>[@<unit-address>]
```

예:

```text
serial@3100000
```

- `name` → 장치 종류를 알아보기 쉬운 이름
- `unit-address` → 해당 Device의 Address를 표현할 때 사용

> ⚠️ 최상위 Node는 CPU가 아니라 `/` Root Node이다. `cpus`는 Root 아래의 Child Node이다.

---

<a id="notion-3ed1d46c18fc80479118f8ccadc65982"></a>

### Property

```text
property = value;
```

Node의 **Hardware 정보나 설정값**을 표현한다.

주요 Property:

```text
compatible
reg
#address-cells
#size-cells
ranges
```

<a id="notion-3ed1d46c18fc8012a80be5c1ea27176a"></a>

#### `compatible`

Device와 Driver를 Matching할 때 사용하는 문자열.

```text
compatible = "my-pdev";
```

<a id="notion-3ed1d46c18fc8043af19d067f244418d"></a>

#### `reg`

Device의 Address / Size 정보를 표현한다.

```text
reg
→ Address + Size
→ 표현 형식은 부모 Node의
  #address-cells / #size-cells에 따라 결정
```

<a id="notion-3ed1d46c18fc8035aa8bf38f8adce947"></a>

#### `#address-cells`

주소를 몇 개의 Cell로 표현할지 지정한다.

<a id="notion-3ed1d46c18fc80ce867dd938c634359c"></a>

#### `#size-cells`

크기를 몇 개의 Cell로 표현할지 지정한다.

<a id="notion-3ed1d46c18fc80778ee2f43729d0fa41"></a>

#### `ranges`

Child Bus 주소와 Parent Bus 주소 사이의 **주소 변환 관계**를 표현한다.

---

<a id="notion-3ed1d46c18fc80ed931ff647a5b8152e"></a>

### MYDEV Device Tree 예제

```text
my_pdev@2212880 {
    compatible = "my-pdev";
    reg = <0x0 0x02212880 0x0 0x20>;
    interrupt-parent = <0xf3>;
    interrupts = <133 2>;
    led_status = <0>;
};
```

구조:

```text
my_pdev@2212880
│
├─ compatible
│  → Driver Matching 정보
│
├─ reg
│  → Device의 Address / Size
│
├─ interrupt-parent
│  → 연결된 Interrupt Controller
│
├─ interrupts
│  → Interrupt 번호 / 특성
│
└─ led_status
   → Driver에서 사용할 추가 설정값
```

<a id="notion-3ed1d46c18fc80a0af9cc9edc1645745"></a>

#### `my_pdev@2212880`

```text
my_pdev
→ Node 이름

@2212880
→ Device의 Unit Address
```

`reg`에 설정된 물리 주소 `0x02212880`과 연결된다.

<a id="notion-3ed1d46c18fc805c8569ecd7fbc4f3bb"></a>

#### `compatible`

```text
compatible = "my-pdev";
```

Driver의:

```text
.compatible = "my-pdev"
```

과 Matching된다.

```text
DT compatible
↔
Driver of_match_table
↓
probe()
```

<a id="notion-3ed1d46c18fc8067a44df7a29f688ac3"></a>

#### `reg`

```text
reg = <0x0 0x02212880 0x0 0x20>;
```

Device의 **Memory Address와 Size**를 표현한다.

Driver에서는:

```text
platform_get_resource(pdev, IORESOURCE_MEM, 0);
```

로 가져와 사용할 수 있다.

<a id="notion-3ed1d46c18fc80f08586ea9fc897cdd8"></a>

#### Interrupt 정보

```text
interrupt-parent = <0xf3>;
interrupts = <133 2>;
```

- `interrupt-parent` → 이 Device가 연결된 Interrupt Controller
- `interrupts` → Interrupt 번호와 특성
- 각 Cell의 의미는 Interrupt Controller에 따라 다름

Driver에서는:

```text
platform_get_irq(pdev, 0);
```

로 Linux IRQ 번호를 얻는다.

<a id="notion-3ed1d46c18fc80ed8225d6555fa4f680"></a>

#### `led_status`

```text
led_status = <0>;
```

이번 실습에서 추가한 **사용자 정의 Property**이다.

Driver에서:

```text
device_property_read_u32(
    dev,
    "led_status",
    &led_status
);
```

로 값을 가져와 LED 초기 상태 설정에 사용한다.

<a id="notion-3ed1d46c18fc8083960efe607ff10894"></a>

#### 예제와 Driver 연결

```text
compatible
→ of_match_table
→ Driver Matching

reg
→ platform_get_resource()
→ I/O Memory

interrupt-parent + interrupts
→ platform_get_irq()
→ IRQ

led_status
→ device_property_read_u32()
→ LED 초기 상태
```

## Interrupt 표현

⭐ **중요 ★**

📝 **시험**

Interrupt 계층 구조는 일반 Device Node의 계층과 별도로 구성될 수 있다.

<a id="notion-3ed1d46c18fc8022b3c9f2f690d54405"></a>

### `interrupt-controller`

```text
interrupt-controller;
```

- 해당 Node가 **Interrupt Controller**임을 의미
- 값이 없는 Property

<a id="notion-3ed1d46c18fc8023960ecc9956b475fc"></a>

### `#interrupt-cells`

- `interrupts` 정보를 몇 개의 Cell로 표현할지 지정

<a id="notion-3ed1d46c18fc806f80b0e22b7295e4f1"></a>

### `interrupt-parent`

- 어떤 Interrupt Controller에 연결되는지 지정
- 생략 시 상위 Node에서 설정된 값을 상속할 수 있음

<a id="notion-3ed1d46c18fc802a8f6add5e10055761"></a>

### `interrupts`

- Interrupt 번호와 Trigger 등의 Interrupt 정보 표현
- Cell의 의미는 Interrupt Controller에 따라 다름

핵심:

```text
interrupt-controller
→ 나는 Interrupt Controller

#interrupt-cells
→ Interrupt 정보 Cell 개수

interrupt-parent
→ 연결된 Interrupt Controller

interrupts
→ IRQ 번호 / Trigger 등의 정보
```

## 현재 Kernel의 DT 확인

실행 중인 System의 Device Tree를 DTS 형태로 확인할 수 있다.

```text
sudo dtc -I fs -O dts \
    -o extracted.dts \
    /proc/device-tree
```

```text
/proc/device-tree
↓
DTC
↓
extracted.dts
```

## Platform Driver에서 DT 사용

기존 Platform Device 방식에서는 Driver Code 안에서 직접:

```text
Resource
Platform Data
Platform Device
```

를 정의했다.

DT를 사용하면 Hardware 정보를 **Device Tree에서 제공**한다.

```text
기존 방식

Driver Code
├─ Memory Resource
├─ IRQ Resource
└─ platform_data
```

```text
DT 방식

Device Tree
├─ Memory 정보
├─ Interrupt 정보
└─ 설정 Property
        ↓
Kernel
        ↓
Platform Driver
```

---

<a id="notion-3ed1d46c18fc80a8a5c5c67f1ceb4d05"></a>

### DT와 Driver Matching

Driver에서 DT Matching Table을 정의한다.

```text
static const struct of_device_id my_pdev_of_match[] = {
    {
        .compatible = "my-pdev",
    },
    {},
};

MODULE_DEVICE_TABLE(of, my_pdev_of_match);
```

Platform Driver에 연결:

```text
.driver = {
    .name = DEVICE_NAME,
    .owner = THIS_MODULE,
    .of_match_table = my_pdev_of_match,
},
```

핵심:

```text
DT
compatible = "my-pdev"

        ↕ Matching

Driver
of_match_table
compatible = "my-pdev"

        ↓

probe()
```

DT를 사용할 때는 기존 Platform Device의 `.name` Matching보다 **`compatible`** <strong>↔</strong> **`of_match_table`** <strong>Matching이 핵심</strong>이다.

---

<a id="notion-3ed1d46c18fc80b386ecc97c78e6b4ff"></a>

### `probe()`에서 DT 정보 가져오기

Device와 Driver가 Matching되면:

```text
probe()
```

가 호출되고 DT에 정의된 Hardware 정보를 가져온다.

<a id="notion-3ed1d46c18fc8002af65c3598bf8fcec"></a>

#### Memory Resource

```text
res = platform_get_resource(
    pdev,
    IORESOURCE_MEM,
    0
);
```

```text
DT Memory 정보
↓
platform_get_resource()
↓
Memory Resource
```

사용:

```text
phy_base = res->start;
phy_size = resource_size(res);
```

<a id="notion-3ed1d46c18fc80a58250efcd5ef61cad"></a>

#### IRQ 정보

```text
irq = platform_get_irq(pdev, 0);
```

```text
DT의 interrupts
↓
Kernel
↓
platform_get_irq()
↓
Linux IRQ 번호
```

DT를 통해 얻은 IRQ 번호를 예제에서는:

```text
irq_key = irq;
```

로 사용한다.

<a id="notion-3ed1d46c18fc80ae957adb42b96cb3e0"></a>

#### 일반 Property 읽기

```text
device_property_read_u32(
    dev,
    "led_status",
    &led_status
);
```

```text
DT의 led_status
↓
device_property_read_u32()
↓
led_status 변수
```

기존의 `platform_data` 대신 **DT Property에서 설정값을 가져올 수 있다.**

---

<a id="notion-3ed1d46c18fc80a8bdc3d689b44c0042"></a>

### 가져온 Resource / Property 사용

Memory Resource:

```text
platform_get_resource()
↓
phy_base / phy_size
↓
ioremap()
↓
GPIO Register 접근
```

IRQ:

```text
platform_get_irq()
↓
irq
↓
request_irq()
↓
Interrupt Handler 등록
```

Property:

```text
device_property_read_u32()
↓
led_status
↓
LED 초기 상태 결정
```

<a id="notion-3ed1d46c18fc80458684f1fd0c75f48f"></a>

### DT 사용 시 Platform Device / Driver 등록

⭐ **중요 ★**

📝 **시험**

DT를 사용하지 않는 기존 방식:

```text
platform_device_register(&my_platform_device);
platform_driver_register(&my_platform_driver);
```

```text
Platform Device
→ 코드에서 등록

Platform Driver
→ 코드에서 등록
```

Device Tree를 사용하는 경우에는 **Device 정보가 DT에 존재하고 Kernel이 이를 기반으로 Platform Device를 생성 / 관리**한다.

따라서 Driver Module에서는:

```text
platform_device_register();
platform_device_unregister();
```

를 별도로 호출하지 않는다.

Platform Driver만 등록 / 해제한다.

```text
platform_driver_register(&my_platform_driver);
platform_driver_unregister(&my_platform_driver);
```

시험 핵심:

```text
DT 사용 X
→ Platform Device 등록
→ Platform Driver 등록

DT 사용 O
→ Device 정보는 DT에서 제공
→ Kernel이 Platform Device 생성 / 관리
→ Platform Driver만 등록 / 해제
```

전체 동작:

```text
DT의 Device Node
↓
Kernel이 Platform Device 생성
↓
insmod
↓
platform_driver_register()
↓
compatible ↔ of_match_table
↓
Matching
↓
probe()
↓
Resource / Property 획득
↓
Hardware 초기화
```

제거:

```text
rmmod
↓
platform_driver_unregister()
↓
remove()
```

> 📝 **DT 방식에서는 Device를 코드에서 직접 등록 / 해제하지 않고, Platform Driver만 등록 / 해제한다.**

## 오늘 배운 내용 요약정리

- **Device Tree**

  - Hardware 정보를 Kernel에 전달
  - `DTS → DTC → DTB → Bootloader → Kernel`
- **DT 구조**

  - `Node + Property`
  - `/` → Root Node
  - `compatible`, `reg`, `#address-cells`, `#size-cells`, `ranges`
- **MYDEV DT**

  - `compatible` → Driver Matching
  - `reg` → Memory Resource
  - `interrupts` → Interrupt 정보
  - `led_status` → 사용자 정의 Property
- ⭐ 📝 **Interrupt 표현**

  - `interrupt-controller`
  - `#interrupt-cells`
  - `interrupt-parent`
  - `interrupts`
- **Driver Matching**

  - `compatible ↔ of_match_table`
  - Matching → `probe()`
- **DT 정보 획득**

  - `platform_get_resource()` → Memory
  - `platform_get_irq()` → IRQ
  - `device_property_read_u32()` → Property
- ⭐ 📝 **DT 사용 시**

  - Platform Device → DT 기반으로 Kernel이 생성 / 관리
  - `platform_device_register()` → X
  - `platform_driver_register()` → O

```text
DTS
↓
DTB
↓
Bootloader
↓
Kernel
↓
Platform Device 생성
↓
compatible ↔ of_match_table
↓
probe()
↓
Resource / Property 획득
↓
Hardware 초기화
```
