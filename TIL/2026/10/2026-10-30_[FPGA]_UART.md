# UART 기본 개념

**UART (Universal Asynchronous Receiver/Transmitter)**

MCU, FPGA, 센서 등에서 사용하는 **비동기 직렬 통신 방식**이다.

- **Asynchronous**

  - 별도의 Clock 신호를 사용하지 않음
- **Serial Communication**

  - 데이터를 1bit씩 순차적으로 전송
- **Full-Duplex**

  - TX와 RX를 동시에 처리 가능

<a id="notion-4081d46c18fc80e79ee0d956b851c7ae"></a>

### UART Frame

`IDLE → START → DATA → (PARITY) → STOP`

- **IDLE**: 기본적으로 High
- **START Bit**: 통신 시작, 1bit 시간 동안 `0`
- **DATA Bit**: 5\~8bit
- **PARITY Bit**: 오류 검출용, 설정에 따라 사용
- **STOP Bit**: 통신 종료
- **Baud Rate**: 초당 전송되는 Symbol 수

⭐ UART는 별도 Clock을 공유하지 않기 때문에 **송신기와 수신기의 Baud Rate가 맞아야 한다.**

## UART TX / RX

※ UART의 일반 구조에서는 Parity를 선택적으로 사용할 수 있으며, 아래 강의 RTL 예제는 **Data 8bit(1Byte), Parity 미사용** 기준으로 구현한다.

<a id="notion-4081d46c18fc806ab653d5c8999a9669"></a>

### TX — 송신

1. 전송할 Data를 UART Frame으로 구성
2. Start Bit 전송
3. Data Bit를 순서대로 전송
4. 설정에 따라 Parity Bit 전송
5. Stop Bit 전송

각 Bit는 **Baud Rate에 맞는 일정한 시간 동안 유지**한다.

<a id="notion-4081d46c18fc80689301eaff7f4fbb0d"></a>

### RX — 수신

1. RX의 **Falling Edge**를 감지
2. Start Bit 후보로 판단하고 Sampling 시작
3. Bit 중앙에서 Start Bit를 확인
4. Data / (Parity) / Stop Bit 수신
5. 8bit Data(1Byte) 완성

## UART 장단점

**장점**

- 회로가 간단함
- 별도의 Clock 배선 불필요
- MCU, FPGA, 센서 등에서 널리 사용

**단점**

- 비교적 느림
- 송신/수신 Baud Rate를 정확히 맞춰야 함
- 기본적으로 1:1 통신 구조라 다중 Node 통신에 불리함

## Baud Rate와 Clock

FPGA의 System Clock을 이용하여 **UART의 1bit 전송 Timing**을 만든다.

<a id="notion-4081d46c18fc80fbafedd3bfa9a9a639"></a>

### 100MHz System Clock

`1 Clock = 10ns`

<a id="notion-4081d46c18fc803a9223cdd1763fa821"></a>

### 115200bps

```text
100,000,000 / 115,200 ≒ 868.06 Clock/bit
```

→ 약 **868 Clock마다 UART 1bit를 송·수신**

<a id="notion-4081d46c18fc80a799ceeeefdf67177f"></a>

### 9600bps

100MHz System Clock 기준:

```text
100,000,000 / 9600
≒ 10,416.67 Clock/bit
```

1 Clock이 10ns이므로:

```text
10,416.67 × 10ns
≒ 104,166.7ns
≒ 104.167µs
```

→ 9600bps에서는 약 **10,417 Clock마다 1bit**를 송·수신한다.

⚠️ **강의자료 계산 주의**

강의자료에는 9600bps 계산 과정에서 `10.416µs`, `1041.6 count` 등의 값이 표시되어 있으나, `100MHz = 10ns/Clock` 조건과 맞지 않는다.

→ 구현 시에는 **약 104.167µs/bit, 10,416.67 Clock/bit**를 기준으로 계산한다.

## UART 데이터 전송 순서

예: ASCII `'5'`

- ASCII `'5'` = `0x35`
- Start Bit를 먼저 전송
- Data는 **LSB부터 전송**
- Data 전송 후 Stop Bit
- 전송하지 않을 때 TX는 High 상태 유지

```text
IDLE
 ↓
START BIT
 ↓
DATA BIT 0
 ↓
DATA BIT 1
 ↓
...
 ↓
DATA BIT 7
 ↓
STOP BIT
 ↓
IDLE
```

## 전체 Block Diagram

강의자료의 전체 구조에서는 다음과 같은 Module들이 연결된다.

```text
Top
├─ uart_controller
├─ control_tower
├─ btn_debouncer
└─ fnd_controller
```

`uart_controller` 내부:

```text
uart_controller
├─ tick_generator
├─ data_sender
├─ uart_tx
└─ uart_rx
```

<a id="notion-4081d46c18fc80ef8831e811248af8f2"></a>

### tick\_generator

일정 주기의 Tick 생성.

강의 예제에서는 **1Hz Tick**을 만들어 `data_sender`의 전송 Trigger로 사용.

<a id="notion-4081d46c18fc80f6a1aaceb5f998491d"></a>

### data\_sender

보낼 Data가 있고 `tx_busy == 0`이면:

- Data를 `tx_data`에 전달
- `tx_start = 1`
- `uart_tx`의 송신 시작

<a id="notion-4081d46c18fc809fb4ced6e5cc41d7c1"></a>

### uart\_tx

`tx_data`의 1Byte를 UART Frame으로 변환하여 **TX Port로 1bit씩 전송**.

전송 중:

```text
tx_busy = 1
```

→ 상위 Module이 전송 중인 `tx_data`를 덮어쓰지 못하도록 함.

<a id="notion-4081d46c18fc806cb3aee5c184e1e494"></a>

### uart\_rx

RX Port로 들어오는 데이터를 1bit씩 수신.

8bit 수신 완료 후:

- `data_out`에 1Byte 완성
- `rx_done = 1`

→ 상위 Module이 Data를 읽을 수 있도록 알림.

## UART TX FSM

주요 State:

```text
IDLE
 ↓
START_BIT
 ↓
DATA_BITS
 ↓
STOP_BIT
 ↓
IDLE
```

<a id="notion-4081d46c18fc8063a5b9cebb42e6f909"></a>

### IDLE

```text
tx      = 1
tx_busy = 0
tx_done = 0
```

`tx_start == 1`이 되면:

- `tx_data`를 내부 Register에 저장
- `tx_busy = 1`
- Bit Count 초기화
- `START_BIT`로 이동

<a id="notion-4081d46c18fc806eb40dd35a4b6abcd6"></a>

### START\_BIT

TX를 `0`으로 출력.

1bit 시간이 지나면:

`DATA_BITS`로 이동.

<a id="notion-4081d46c18fc8031bef6f981768eda5c"></a>

### DATA\_BITS

저장된 Data를 **LSB부터 1bit씩 전송**.

`r_bit_cnt`를 증가시키며 8bit 전송.

<a id="notion-4081d46c18fc806ca80bdb1b0ceb6592"></a>

### STOP\_BIT

TX를 `1`로 유지.

Stop Bit 전송 완료 후:

- `tx_busy = 0`
- `tx_done = 1`
- `IDLE`로 복귀

주요 Register:

```text
reg [1:0]  r_state;
reg [3:0]  r_bit_cnt;
reg [7:0]  r_data_reg;
reg [15:0] r_baud_cnt;
reg        r_baud_tick;
```

## UART RX Oversampling

UART RX는 송신 측의 Clock을 직접 받지 않기 때문에 **수신 Data를 Sampling하여 Bit 위치를 판단**한다.

강의자료에서는 **16배 Oversampling**을 사용한다.

```text
BAUD_RATE    = 9600
Oversampling = 16

100,000,000 / (9600 × 16)
≒ 651.04 Clock/Sample
```

→ 약 **651 Clock마다 Sampling Tick 발생**

1bit 구간을 16번 Sampling하므로:

```text
약 651 Clock/Sample × 16 Sample/bit
≈ 10,416 Clock/bit
```

→ 9600bps의 **약 10,416.67 Clock/bit**와 대응한다.

강의자료의 Oversampling 개념 설명에서는 Bit의 안정적인 중앙 지점인 **8번째 Sample 부근**에서 값을 확인하는 방식으로 설명한다.

⭐ **Oversampling 목적**

- Start Bit 위치 판단
- Bit 중앙에서 안정적으로 Data Sampling
- 송·수신 Timing 오차에 대응
- Noise에 대한 안정성 향상

<a id="notion-4081d46c18fc8029b995c6aceda9e412"></a>

## UART RX FSM

주요 State:

```text
IDLE
 ↓
START_BIT
 ↓
DATA_BITS
 ↓
STOP_BIT
 ↓
IDLE
```

<a id="notion-4081d46c18fc8091a6fbec22e729201d"></a>

### IDLE

RX가 `0`이 되는지 확인.

```text
rx == 0
```

→ Start Bit 후보 감지

<a id="notion-4081d46c18fc802e97b8ceeeada170a2"></a>

### START\_BIT

Oversampling Tick을 Count하면서 Start Bit를 확인.

Bit 중앙에서 실제로 RX가 `0`인지 확인한 뒤 Data 수신 시작.

<a id="notion-4081d46c18fc80ae821ec34662fcb081"></a>

### DATA\_BITS

각 Data Bit를 Sampling하여:

```text
r_data_reg[r_bit_cnt] <= rx;
```

8bit가 완성될 때까지 반복.

<a id="notion-4081d46c18fc80c6a591d754b715ab69"></a>

### STOP\_BIT

Stop Bit를 수신한 뒤:

- `data_out = r_data_reg`
- `rx_done = 1`
- `IDLE` 복귀

주요 Register:

```text
reg [1:0]  r_state;
reg [3:0]  r_bit_cnt;
reg [7:0]  r_data_reg;
reg [15:0] r_baud_cnt;
reg        r_baud_tick;
reg [3:0]  r_baud_tick_cnt;
```

## TX와 RX 핵심 차이

**TX**

- 이미 알고 있는 Data를 Baud Rate에 맞춰 출력
- 1bit마다 일정 시간 유지

**RX**

- 송신 측의 Clock을 직접 알 수 없음
- Start Bit를 감지한 뒤 Sampling
- Oversampling을 이용해 적절한 Sampling 위치 결정

```text
TX : Baud Timing에 맞춰 출력
RX : Baud Timing에 맞춰 Sampling
```

## Multiple Driver 문제

하나의 `txline`에 여러 Module이 동시에 값을 출력하려 하면 **Multiple Driver 문제**가 발생할 수 있다.

강의자료 예:

- Sensor 1 TX
- Sensor 2 TX
- 동일한 TX Line 사용

두 Module이 같은 Signal을 직접 Drive하면 충돌 발생.

<a id="notion-4081d46c18fc8022b834f8f84e187610"></a>

### 강의자료 해결 방법

각 Sensor에 **3-State Buffer**를 두고,

```text
tx_busy == 1
```

인 Sensor만 `txline`을 점유하도록 구성한다.

```text
Sensor 1 ─┐
          ├─ 3-State Buffer ─→ txline
Sensor 2 ─┘

현재 송신 중인 Module만 Line 사용
```

⭐ FPGA에서 **하나의 Signal을 여러 Logic이 동시에 Drive하지 않도록 설계**해야 한다.

## 핵심 흐름

```text
UART
 ↓
비동기 직렬 통신
 ↓
TX / RX 독립 동작
 ↓
Baud Rate로 Bit Timing 결정
 ↓
TX : Data → UART Frame → 1bit씩 전송
RX : Start Bit 감지 → Oversampling → 1Byte 복원
 ↓
FSM으로 송·수신 상태 제어
```

<a id="notion-4081d46c18fc8053aae5c978c71dee5d"></a>

### 핵심 신호

```text
tx_start : TX 전송 시작 요청
tx_busy  : TX 전송 중
tx_done  : TX 전송 완료

rx       : UART 수신 Port
data_out : 수신 완료된 1Byte
rx_done  : 1Byte 수신 완료
```

⭐ **TX는 Baud Rate에 맞춰 Bit를 내보내고, RX는 Oversampling을 통해 Bit의 중앙을 찾아 데이터를 읽는 것이 핵심이다.**
