## Process

Program이 실행되면 **Process**가 된다.

```text
Program
→ Process
→ fork()
→ exec()
→ wait()
→ 종료
```

- Process마다 독립된 Address Space
- `fork()` → 부모 / 자식 Process 생성
- `exec()` → 현재 Process를 다른 Program으로 교체
- `wait()` → 자식 종료 대기
- Signal → Process에 Event 전달 / 제어

---

<a id="notion-3ed1d46c18fc8056b938e1c375dd96c2"></a>

## IPC — Process 간 통신

Process들은 기본적으로 메모리가 독립되어 있으므로 별도의 IPC가 필요하다.

```text
Process ↔ Process
```

주요 방식:

- Pipe / FIFO → 데이터 흐름
- Shared Memory → 같은 Memory 영역 공유
- Message Queue → Message 단위 전달

---

<a id="notion-3ed1d46c18fc80398e8cc9646631f651"></a>

## Thread

하나의 Process 안에서 여러 실행 흐름을 만든다.

```text
Process
├─ Thread
├─ Thread
└─ Thread
```

- 같은 Process의 자원을 공유
- Process보다 생성 / 전환 부담이 작음
- 자원 공유 때문에 동기화 필요
- Semaphore 등 사용
- Race Condition / Deadlock 주의

# Linux Kernel

<a id="notion-3ed1d46c18fc80699884f957b85a09fd"></a>

## User Space → Kernel

Application이 Kernel 기능을 사용하려면 **System Call**을 사용한다.

```text
Application
    ↓
System Call
    ↓
Kernel
```

Kernel의 주요 역할:

- Process 관리
- Memory 관리
- File System 관리
- Device 관리

---

<a id="notion-3ed1d46c18fc80b9b50dec51b907962f"></a>

## VFS

여러 File System을 공통 Interface로 다룬다.

```text
Application
→ VFS
→ 실제 File System
→ 저장 장치
```

주요 객체:

- `super_block`
- `inode`
- `dentry`
- `file`

---

<a id="notion-3ed1d46c18fc80daacbaddade65fc5d1"></a>

# Device Driver

Hardware를 Linux Kernel에서 제어하기 위한 Code.

```text
Application
    ↓
Device File (/dev/...)
    ↓
Device Driver
    ↓
Hardware
```

Device File:

> Application과 Device Driver 사이의 매개체

Driver에서는 주로 다음 동작을 구현한다.

```text
open()
read()
write()
ioctl()
release()
```

---

<a id="notion-3ed1d46c18fc800ab3d8e94b7c2b95a5"></a>

## Hardware Register 접근

Peripheral의 Register는 물리 주소에 존재한다.

```text
Hardware 물리 주소
    ↓
ioremap()
    ↓
Kernel 가상 주소
    ↓
ioread() / iowrite()
    ↓
Hardware 제어
```

즉 Driver가 Register를 읽고 쓰면서 GPIO 등의 Hardware를 실제로 제어한다.

---

<a id="notion-3ed1d46c18fc80f89734c358838f1c0d"></a>

# Interrupt

Hardware에서 Event가 발생했을 때 CPU에 알리는 방식.

```text
Hardware Event
    ↓
Interrupt
    ↓
Interrupt Handler
    ↓
Driver 처리
```

Interrupt Context에서는:

- Sleep X
- Scheduling X
- 오래 걸리는 작업 X
- 가능한 빠르게 처리 후 Return
- 긴 작업 → `thread_fn`, Workqueue 등으로 넘김

---

<a id="notion-3ed1d46c18fc80d6bb54ffde180738ff"></a>

# Device Model / Platform Driver

Linux에서는 Device와 Driver를 분리하여 관리한다.

```text
Platform Device
       ↕ Matching
Platform Driver
       ↓
     probe()
```

Matching되면:

```text
Device 발견
→ Driver Matching
→ probe()
→ Resource 획득
→ Hardware 초기화
```

Device가 제거되거나 Driver가 해제되면 `remove()`가 호출된다.

---

<a id="notion-3ed1d46c18fc809d9a7be7f021dc4943"></a>

# Resource

Driver가 Hardware를 제어하기 위해 필요한 정보.

예:

```text
Memory Address
IRQ
기타 설정값
```

기존 방식:

```text
C Code 안에 Resource 정의
→ Platform Device 등록
→ Driver가 probe()에서 Resource 획득
```

핵심:

> Device가 Hardware 정보를 가지고 있고, Driver가 `probe()`에서 받아서 사용한다.

---

<a id="notion-3ed1d46c18fc80459542f6c7a7f66647"></a>

# Device Tree

Hardware 정보를 Kernel Code와 분리하여 표현한다.

```text
Hardware 정보
    ↓
DTS
    ↓
DTC
    ↓
DTB
    ↓
Bootloader
    ↓
Kernel
```

DT는 **Node + Property** 구조이다.

주요 Property:

- `compatible` → Driver Matching
- `reg` → Memory Resource
- `interrupts` → Interrupt 정보
- 사용자 정의 Property → 추가 설정값

---

<a id="notion-3ed1d46c18fc80ccad65e67b41ec12dd"></a>

## Device Tree + Platform Driver

```text
DT
↓
Kernel이 Platform Device 생성 / 관리
↓
compatible ↔ of_match_table
↓
Driver Matching
↓
probe()
↓
Resource / Property 획득
↓
Hardware 초기화
```

Driver에서는 주로:

```text
platform_get_resource()
platform_get_irq()
device_property_read_u32()
```

등으로 DT의 정보를 가져와 사용한다.

DT를 사용하면 Driver Code에서 Platform Device를 직접 등록하지 않고:

```text
platform_device_register()   → X
platform_device_unregister() → X

platform_driver_register()   → O
platform_driver_unregister() → O
```

# 임베디드 관점의 핵심 흐름

```text
Application
    ↓
open() / read() / write() / ioctl()
    ↓
System Call
    ↓
Device File / VFS
    ↓
Device Driver
    ↓
Hardware Register / Interrupt
    ↓
Hardware
```

그리고 Hardware 정보는:

```text
Device Tree
    ↓
Kernel
    ↓
Platform Device 생성 / 관리
    ↓
Platform Driver Matching
    ↓
probe()
    ↓
Resource / Property 획득
    ↓
Hardware 초기화
```
