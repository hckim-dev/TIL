# 🎛️ ADC (Analog-to-Digital Converter) 총정리

<a id="notion-3ab1d46c18fc803884b6dbbc0cc6bd72"></a>

## 1\. 📌 ADC 기본 개념 및 스펙

아날로그 신호(연속적인 전압)를 MCU가 처리할 수 있는 디지털 수치(분지된 정수 값)로 변환하는 장치

|  |  |  |
| --- | --- | --- |
| **항목** | **스펙 / 특징** | **비고** |
| **변환 방식** | 축차 비교형 (Successive Approximation, SAR) | 빠르고 정확함 |
| **해상도 (Resolution)** | **12-bit** ($0 \sim 4095$, 총 4096단계) | 10-bit / 8-bit / 6-bit 설정도 가능 |
| **입력 전압 범위** | $V_{SSA} \sim V_{DDA}$ (보통 $0\,\text{V} \sim 3.3\,\text{V}$) | 기준 전압 $V_{REF+}$ 대비 비례 변환 |
| **채널 수** | 외부 최대 16채널 + 내부 2채널 (온도 센서, $V_{REFINT}$) |  |
| **최대 클럭 (ADCCLK)** | <strong>최대</strong> **$14\,\text{MHz}$**<br> | APB2 클럭을 분주하여 사용 (`ADCPRE`) |

<a id="notion-3ab1d46c18fc801c8c62e40d183a0bf0"></a>

## 2\. ⚙️ 핵심 동작 모드 (Operation Modes)

<a id="notion-3ab1d46c18fc80468da0eb887b0478f6"></a>

### ① 단일 변환 모드 (Single Conversion Mode)

- **동작:** 명령(소프트웨어/외부 트리거)이 들어오면 **딱 1번만 변환** 후 멈춥니다.
- **사용처:** 가변저항 스위치 상태 확인, 1회성 전압 측정.

<a id="notion-3ab1d46c18fc807fb0fdc1329cdde41e"></a>

### ② 연속 변환 모드 (Continuous Conversion Mode)

- **동작:** 한 번 시작하면 계속해서 끊임없이 변환을 반복합니다 (`CONT = 1`).
- **사용처:** 실시간 볼륨/속도 제어, 가변저항 실시간 모니터링.

<a id="notion-3ab1d46c18fc8038a199cba56478ef65"></a>

### ③ 스캔 모드 (Scan Mode)

- **동작:** 설정한 여러 채널(예: Ch0 $\rightarrow$ Ch1 $\rightarrow$ Ch2)을 **순차적으로 자동 스캔**하며 변환합니다 (`SCAN = 1`).
- **주의:** 스캔 모드로 여러 채널을 읽을 때는 데이터 덮어쓰기를 막기 위해 **DMA 사용이 거의 필수적**입니다.

<a id="notion-3ab1d46c18fc80dc83ebd4fc3ca718fa"></a>

## 3\. 🎯 채널 그룹 구분 (Regular vs Injected)

STM32 ADC는 채널을 **두 개의 독립 그룹**으로 나누어 관리합니다.

```text
[ Regular Channel Sequence (Ch0 -> Ch1 -> Ch2) ] ─── 변환 중...
                               ▲
                      Injected Trigger 발생! (우선순위 인터럽트)
                               │
            [ Injected Channel (Ch5) 변환 완료 후 원래 작업 복귀 ]
```

|  |  |  |
| --- | --- | --- |
| **구분** | **일반 채널 (Regular Group)** | **주입 채널 (Injected Group)** |
| **최대 채널 수** | 최대 **16개** 순차 변환 | 최대 **4개** 순차 변환 |
| **저장 레지스터** | **단 1개의 공용 레지스터** (`ADC_DR`) | **각 채널별 전용 레지스터** (`ADC_JDR1~4`) |
| **특징** | 일반적인 데이터 수집용 | **긴급/우선순위 처리용** (변환 중 인터럽트 가능) |

<a id="notion-3ab1d46c18fc80728c87e89e2386d5e7"></a>

## 4\. 📐 전압 계산 공식 &amp; 데이터 정렬

<a id="notion-3ab1d46c18fc8081b399e2b3b7c0c8ac"></a>

### ① 아날로그 전압 계산식

$V_{IN} = \frac{\text{ADC\_Value} \times V_{REF+}}{4095}$

- 예: $12\text{-bit ADC}$ 읽은 값이 `2048`, $V_{REF+} = 3.3\,\text{V}$ 일 때:

  $V_{IN} = \frac{2048 \times 3.3}{4095} \approx 1.65\,\text{V}$

<a id="notion-3ab1d46c18fc8089a7b8e030553947ee"></a>

### ② 데이터 정렬 (Data Alignment)

`ADC_DR` 레지스터는 16-bit이지만 ADC 결과는 12-bit이므로 정렬 방향을 선택합니다.

- **우측 정렬 (Right Alignment - 기본값):** 하위 12비트에 데이터 저장. (`0x0000` \~ `0x0FFF`, 일반적인 연산용)
- **좌측 정렬 (Left Alignment):** 상위 12비트에 데이터 저장. (8비트 오디오/DSP 처리 시 유용)

<a id="notion-3ab1d46c18fc8040a21fd7ce629083f6"></a>

## 5\. 🚀 ADC 수집 방식 3가지 비교

```text
1. Polling (대기 방식)    : CPU가 변환 끝날 때까지 while문으로 대기 ❌ (CPU 점유율 높음)
2. Interrupt (인터럽트)   : 변환 끝나면 EOC ISR 호출 ⭕ (CPU 자원 절약)
3. DMA (직접 메모리 접근)  : CPU 개입 없이 SRAM으로 자동 전송 🔥 (고속/다채널 최적)
```

|  |  |  |  |
| --- | --- | --- | --- |
| **방식** | **특징** | **장점** | **단점** |
| **Polling** | `EOC` 플래그 확인 대기 | 구현이 가장 간단함 | CPU가 무한 대기하므로 성능 저하 |
| **Interrupt** | 변환 완료 시 `EOC` 인터럽트 발생 | CPU 효율적 활용 | 채널이 많으면 인터럽트 오버헤드 큼 |
| **DMA** | ADC 결과를 SRAM 메모리로 자동 복사 | <strong>CPU 개입 0%</strong>, 최고 속도 | 설정해야 할 레지스터가 많음 |

<a id="notion-3ab1d46c18fc80a59d8fd3f1f30b199f"></a>

## 6\. 📝 시험 &amp; 면접 대비 단골 Q&amp;A

> **Q1. ADC 샘플링 타임(Sampling Time)이 왜 필요한가요?**
>
> - **A:** ADC 내부의 샘플앤홀드(Sample &amp; Hold) 커패시터에 입력 전압을 충분히 충전할 시간이 필요하기 때문입니다. 입력 임피던스가 높은 센서일수록 샘플링 타임을 길게 잡아야 정확하게 측정됩니다.

> **Q2. 다채널 ADC 스캔 시 왜 DMA를 함께 써야 하나요?**
>
> - **A:** Regular 그룹의 데이터 레지스터(`ADC_DR`)는 1개밖에 없어서, DMA를 쓰지 않으면 다음 채널이 변환되었을 때 이전 채널 데이터가 덮어씌워져 사라지기 때문입니다.

```c
void ADC1_Init(void)
{
	// GPIOA 클럭 활성화 (AHB1ENR: Bit 0)
	Macro_Set_Bit(RCC->AHB1ENR, 0U);

	// PA6 핀 아날로그 모드 설정 (MODER: 6번 핀 -> offset 12, mode 0x3)
	Macro_Write_Block(GPIOA->MODER, 0x3, 0x3, 12U);

	// ADC1 클럭 활성화 (APB2ENR: Bit 8)
	Macro_Set_Bit(RCC->APB2ENR, 8U);

	// CH6 샘플링 타임 설정: 480 Cycles (SMPR2: 6번 채널 -> offset 18, value 0x7)
	Macro_Write_Block(ADC1->SMPR2, 0x7, 0x7, 18U);

	// 변환 시퀀스 길이: 1개 (SQR1: offset 20, value 0x0)
	Macro_Write_Block(ADC1->SQR1, 0xF, 0x0, 20U);

	// 첫 번째 순서(SQ1)로 CH6 지정 (SQR3: offset 0, value 6)
	Macro_Write_Block(ADC1->SQR3, 0x1F, 6U, 0U);

	// ADC Prescaler 설정: PCLK2 / 6 = 16MHz (ADC->CCR: offset 16, value 0x2)
	Macro_Write_Block(ADC->CCR, 0x3, 0x2, 16U);

	// ADC1 전원 켜기 (CR2: ADON Bit 0)
	Macro_Set_Bit(ADC1->CR2, 0U);
}

unsigned short ADC1_Read(void)
{
	// 1) 변환 시작 (CR2: SWSTART Bit 30)
	Macro_Set_Bit(ADC1->CR2, 30U);

	// 2) 변환 완료 대기 (SR: EOC Bit 1이 1이 될 때까지)
	while (!Macro_Check_Bit_Set(ADC1->SR, 1U))
		;

	// 3) EOC 플래그 클리어
	Macro_Clear_Bit(ADC1->SR, 1U);

	// 4) 12비트 변환 결과 읽기 (0 ~ 4095)
	return (unsigned short)(ADC1->DR & 0xFFFU);
}
```
