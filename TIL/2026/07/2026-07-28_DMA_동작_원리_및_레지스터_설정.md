# 🚀 DMA (Direct Memory Access) 총정리

## 1. 📌 DMA란 무엇인가? (개념 및 존재 이유)

DMA는 CPU의 개입 없이 주변장치(Peripheral)와 메모리(SRAM), 또는 메모리와 메모리 간에 데이터를 고속으로 직접 전송하는 전용 하드웨어 제어기입니다.

### 💡 기존 방식 vs DMA 방식 비교

```plain text
[ 기존 방식 (CPU Polling / Interrupt) ]
  ADC/UART ──(데이터 발생)──▶ CPU ──(읽고 쓰기)──▶ SRAM
  * 문제점: 데이터가 들어올 때마다 CPU가 일을 멈추고 복사 작업에 매달려야 함.

[ DMA 방식 ]
  ADC/UART ──────────(DMA Controller)──────────▶ SRAM
                       (CPU는 딴일 중!)
  * 장점: CPU는 데이터 전송 신경 안 쓰고 연산/제어 알고리즘만 집중 수행 가능!
```

## 2. ⚙️ DMA 전송의 3가지 유형

| 전송 유형 (Mode) | 설명 | 주요 사용 예시 |
|---|---|---|
| Peripheral to Memory | 주변장치 수신 데이터 \rightarrow 메모리 | ADC 연속 변환 수집, UART Rx(수신) |
| Memory to Peripheral | 메모리 데이터 \rightarrow 주변장치 출력 | UART Tx(대량 송신), DAC 음원/파형 출력, SPI 디스플레이 전송 |
| Memory to Memory | 메모리 특정 영역 \rightarrow 다른 메모리 영역 | 큰 배열/버퍼 복사 (memcpy 대체) |

## 3. 🎯 DMA를 쓰면 '무조건 좋은' 3가지 상황

### ① [최고의 궁합] 다채널 ADC 스캐닝 (Multi-Channel ADC) 🔥

- 이유: STM32의 ADC 일반 그룹(Regular Group)은 데이터 레지스터(ADC_DR)가 단 1개뿐입니다.
- 문제: Ch0, Ch1, Ch2를 순차적으로 스캔할 때 CPU가 제때 읽어가지 않으면 다음 채널 데이터가 이전 채널 데이터를 덮어써서(Overrun) 손실됩니다.
- DMA 해결: ADC 변환 완료(EOC) 신호가 뜰 때마다 DMA가 배열(uint16_t adc_buf[3])에 알아서 0번, 1번, 2번 순서대로 착착 복사해 줍니다.
### ② 고속 시리얼 통신 (UART / SPI / I2C 대량 전송)

- 이유: UART로 1000\text{ Byte} 텍스트를 출력하거나 SPI로 TFT-LCD 화면에 320 \times 240 이미지를 그릴 때, 1 바이트씩 인터럽트로 보내면 초당 수만 번의 인터럽트가 발생해 CPU가 마비됩니다.
- DMA 해결: "메모리 A번지부터 1000\text{ Byte}를 SPI로 쏴라!" 하고 DMA를 켜두면, CPU는 0.001초도 낭비하지 않고 다음 코드를 실행합니다.
### ③ 실시간 신호 처리 및 센서 모니터링 (Circular Mode)

- DMA의 순환 모드(Circular Mode)를 켜면, 지정한 메모리 버퍼가 다 찼을 때 다시 처음 0번지부터 덮어쓰며 무한 반복합니다.
- 백그라운드에서 실시간으로 항상 최신 센서 값이 메모리에 자동 갱신되므로, CPU는 필요할 때 버퍼의 값만 쏙 가져다 쓰면 됩니다.

## 4. 💡 UART2 TX DMA 전송 예제

### ① 초기화 및 설정 (dma.c - DMA1_Stream6_USART2_TX_Start)

1. RCC->AHB1ENR Bit 21 활성화 \rightarrow DMA1 클럭 ON.
1. PAR = &USART2->DR \rightarrow 목적지 주변장치를 UART2 Data Register로 지정.
1. M0AR = src_addr \rightarrow 원본 데이터를 보낼 문자열 메모리 주소 지정.
1. NDTR = num \rightarrow 전송할 문자열 길이 설정.
1. DIR = 01 (Memory-to-Peripheral), MINC = 1 (메모리 주소 자동 증가).
1. USART2->CR3 Bit 7 (DMAT) 비트 Set \rightarrow UART2 하드웨어에게 DMA 전송 요청(Trigger) 허용.
1. DMA1_Stream6->CR Bit 0 (EN = 1) \rightarrow DMA 전송 개시!
### ② 동작 중 (main.c & Exception.c)

- CPU는 printf나 for문으로 갇혀있지 않고 다른 실시간 업무(if(TIM4_Expired))를 100% 속도로 계속 처리합니다.
- DMA가 알아서 UART2 DR 레지스터로 1바이트씩 쏩니다.
- 전송이 완료되면 DMA1_Stream6_IRQHandler() 인터럽트가 실행되어 DMA1_STREAM6_DONE = 1 플래그를 세우고 다음 문장을 준비합니다.
## 🔍 실무에서 알아야 할 중요한 내용

### 1. ⚠️ UART 송신 시 TXE vs TC 플래그의 명확한 차이

- TXE (Transmit Data Register Empty): 송신 버퍼 레지스터가 비어서 "다음 글자를 써도 됨"을 의미 (아직 핀으로 신호가 나가는 중일 수 있음).
- TC (Transmission Complete): 쉬프트 레지스터까지 완전히 비어서 "마지막 1비트까지 안테나/핀으로 다 나감"을 의미.
- DMA 실무 적용 시: DMA 전송 직전에 Uart2_Wait_for_TX_Complete()를 불러주는 이유는, 이전 데이터가 핀 밖으로 완전히 다 나가기도 전에 DMA가 새로 버퍼를 건드리는 충돌을 막기 위함입니다.
### 2. 🔄 Circular Mode (순환 모드) 동작 원리

- CR 레지스터의 CIRC 비트를 1로 설정하면, NDTR 카운터가 0이 되는 순간 자동으로 처음에 설정했던 원본 NDTR 값과 메모리 주소로 복구(Auto-Reload)됩니다.
- ADC 다채널 연속 스캔이나 UART Ring Buffer 수신 시 while문 없이 무한히 백그라운드 데이터 수집을 가능하게 해주는 핵심 모드입니다.
### 3. 🚨 캐시(Cache)와 메모리 일관성 (Cortex-M4/M7 주의사항)

- CPU가 SRAM의 데이터를 수정했을 때 메모리 캐시(D-Cache)에만 남아있고 실제 SRAM에 아직 반영되지 않았을 경우, DMA가 옛날 데이터를 읽어서 전송하는 오류가 생길 수 있습니다.
- 이럴 경우 코드상에서 SCB_CleanDCache() 등의 함수로 캐시 flush 처리를 해주어야 함을 알고 계시면 좋습니다.
