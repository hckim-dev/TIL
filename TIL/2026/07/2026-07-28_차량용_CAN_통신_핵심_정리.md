# 🚗 CAN (Controller Area Network) 통신 완벽 정리

## 1. 📌 CAN 통신의 등장 배경 및 기본 특징

### ① 등장 배경 (왜 CAN을 쓰는가?)

- 고전적 방식: 주제어기(Main Controller) 하나에 자동차 내 모든 부품을 1:1 전선(Harness Wire)으로 직접 연결 \rightarrow 배선 중량 증가, 복잡도 및 원가 상승.
- CAN 방식: 하네스 와이어를 통신 네트워크 버스로 통합. 각 부품이 독립된 ECU(Electronic Control Unit)가 되어 분산 제어를 수행.
- 장점: 배선 간소화로 차량 무게 및 원가 절감, 신뢰성 향상, SW 수정 없이 ECU의 자유로운 추가/제거 가능.
### ② CAN의 주요 특징

- 비동기 직렬 통신 (Asynchronous Serial): 별도의 클럭선 없이 약속된 Baud Rate(bps)로 동기화하여 통신.
- 차동 신호 (Differential Signaling): CAN_H, CAN_L 두 가닥의 전압 차로 신호를 판별하여 노이즈에 매우 강함.
- 멀티마스터 (Multi-Master) & 브로드캐스팅 (Broadcasting): 특정 Master 없이, 버스가 비어 있으면 누구나 메시지를 송신 가능. 수신자 주소 없이 Message ID를 버스 전체에 뿌림(Broadcasting).
- Acceptance Filtering: 각 ECU는 수신 필터를 통해 자신에게 필요한 Message ID만 선택적으로 수신.
## 2. ⚡ 물리 계층 (Physical Layer) 규격 비교

| 구분 | High-Speed CAN (ISO 11898-2) | Low-Speed CAN (ISO 11898-3) |
|---|---|---|
| 최대 속도 | 최대 1Mbps<br> | 최대 125Kbps<br> |
| 주요 사용처 | PowerTrain (엔진, 미션, 변속기 등) | Body / 샤시 (도어, 시트, 라이트 등) |
| 종단 저항 (Termination) | 버스 양쪽 끝에만 120\,\Omega 설치 (합성 60\,\Omega) | 각 노드에 분산 설치<br> |
| 특징 | 신호 반사파 방지를 위해 종단저항 필수 | Fault Tolerant: 선 하나가 끊겨도 통신 유지 가능 |

## 3. 🧠 핵심 동작 메커니즘 (CSMA/CD-CR & Bus Arbitration)

### ① Dominant(우성, 0) vs Recessive(열성, 1)

- CAN 버스는 Open-Drain(Wired-AND) 구조로 동작.
- 버스 기본 상태는 Recessive (1) 이며, 한 노드라도 Dominant (0) 신호를 쏘면 버스 전체가 0이 됨.
### ② CSMA/CD-CR (충돌 감지 및 충돌 해결)

1. Multiple Access (MA): 버스가 비어있으면 여러 노드가 동시에 메시지 전송 개시.

## 4. 📦 CAN 프레임 종류 및 데이터 구조

### ① 4가지 프레임 종류

1. Data Frame: 실제 데이터를 담아 전송하는 가장 일반적인 프레임.
1. Remote Frame: 다른 노드에게 특정 데이터 전송을 요청하는 프레임.
1. Error Frame: 오류를 감지한 노드가 즉시 버스에 알려 통신을 중단시키는 프레임.
1. Overload Frame: 수신 노드가 바빠서 잠시 전송을 지연시켜 달라고 요청하는 프레임.
### ② CAN 2.0A (Standard) vs CAN 2.0B (Extended)

- Standard (2.0A): 11-bit ID 사용 (2^{11} = 2,048가지 메시지 구분).
- Extended (2.0B): 29-bit ID 사용 (2^{29}가지 메시지 구분).
```plain text
[ Standard CAN 2.0A Data Frame 구조 ]
SOF(1b) ➔ ID(11b) ➔ RTR(1b) ➔ IDE(1b) ➔ r0(1b) ➔ DLC(4b) ➔ Data(0~8B) ➔ CRC(15b) ➔ ACK(2b) ➔ EOF(7b)
```

- Bit Stuffing: SOF부터 CRC 구간까지 동일한 비트가 연속 5개 나오면 반대 비트 1개를 자동 삽입하여 동기 유실을 방지.
## 5. 🚨 에러 처리 및 상태 천이 (Error Handling & States)

자동차 안전의 핵심 메커니즘입니다.

### ① 5가지 통신 오류 유형

1. Bit Error: 자기가 보낸 비트와 버스에서 읽은 비트가 다를 때.
1. ACK Error: 송신 후 ACK 슬롯에서 수신 노드의 ACK(0) 신호를 받지 못했을 때.
1. Stuff Error: 동일 비트가 6개 연속으로 검출되었을 때.
1. Form Error: EOF, ACK Delimiter 등 약속된 고정 비트 서식이 깨졌을 때.
1. CRC Error: 계산한 CRC 값과 수신된 CRC 값이 일치하지 않을 때.
### ② 노드의 3가지 에러 상태 (TEC: 송신 에러 카운터, REC: 수신 에러 카운터)

```plain text
[ Error Active ] ─(TEC/REC > 127)─▶ [ Error Passive ] ─(TEC > 255)─▶ [ Bus Off ]
  (정상 송수신)                        (우선권 제한)                  (통신 마비/차단)
```

- Error Active: TEC/REC < 128. 정상 동작 상태.
- Error Passive: TEC 또는 REC > 127. 정상 송수신은 가능하나, 전송 후 8비트 대기 시간을 가져 버스 우선권을 타 노드에 양보.
- Bus Off: TEC > 255. 해당 ECU가 버스 신호를 망가뜨린다고 판단하여 하드웨어적으로 통신 라인에서 완전히 격리(차단).

# 🚗 CAN 통신 프레임 플로우 & STM32 필터/레지스터 완벽 정리

## 1. 🔄 한눈에 보는 CAN 통신 프레임 플로우

### ① Standard CAN 2.0A (11-bit ID 기본형)

가장 보편적인 기본 프레임 형태입니다.

```plain text
[ BUS IDLE (1) ]
       ↓
[ SOF ] (1bit, Dominant 0) - 통신 시작 알림
       ↓
[ Arbitration Field ] - 우선순위 쟁탈 구간
  • Message ID : 11비트 (ID 번호)
  • RTR : 1비트 (0: Data Frame, 1: Remote Frame)
       ↓
[ Control Field ] - 제어 정보
  • IDE : 1비트 (0: Standard 2.0A 지정)
  • r0  : 1비트 (예약 비트, 0)
  • DLC : 4비트 (보낼 데이터 바이트 수: 0~8 Byte)
       ↓
[ Data Field ] - 실제 데이터 (0 ~ 8 Bytes)
       ↓
[ CRC Field ] - 에러 검출
  • CRC Sequence : 15비트
  • CRC Delimiter : 1비트 (Recessive 1)
       ↓
[ ACK Field ] - 수신 응답
  • ACK Slot : 1비트 (송신자는 1로 쏘고, 수신 성공한 노드들이 0으로 덮어씀)
  • ACK Delimiter : 1비트 (Recessive 1)
       ↓
[ EOF ] (7비트 연속 1) - 프레임 종료
       ↓
[ IFS ] (3비트 연속 1) - 다음 프레임 전송 전 여유 시간
```

### ② Extended CAN 2.0B (29-bit ID 확장형)

메시지 ID 개수를 2,048개에서 수억 개로 확장하기 위한 프레임입니다.

```plain text
[ SOF (0) ]
  ↓
[ Arbitration Field (상위 ID) ] : 11비트 ID + SRR(1) + IDE(1: Extended 표시)
  ↓
[ Arbitration Field (하위 ID) ] : 18비트 ID + RTR(1비트)
  ↓
[ Control Field ] : r1(0), r0(0), DLC(4비트)
  ↓
[ Data Field (0~8B) ] → [ CRC (15b) ] → [ ACK (2b) ] → [ EOF (7b) ]
```

### ③ CAN-FD (Flexible Data-rate)

데이터 전송 속도와 용량을 대폭 올린 차세대 CAN 규격입니다.

```plain text
[ SOF (0) ] → [ ID (11b or 29b) ]
  ↓
[ Control Field (속도 변환 비트 포함) ]
  • RRS / IDE / FDF(1: FD 프레임)
  • BRS : 1비트 (이 비트 직후부터 고속 Baudrate로 클럭 전환!)
  • ESI : 1비트 (에러 상태 표시)
  • DLC : 4비트 (최대 64 Byte 지정)
  ↓
[ Data Field ] : 0 ~ 64 Bytes (고속 전송 ⚡)
  ↓
[ CRC Field ] : 17비트 또는 21비트 (고속 전송 ⚡)
  ↓
[ ACK Slot ] : 일반 속도로 복귀하여 수신 응답 확인
  ↓
[ EOF (7b) ]
```

## 2. 🛡️ STM32 CAN 필터 (Filter Mask vs Filter List) 동작 원리

### 💡 필터가 왜 필요한가요?

CAN 버스는 브로드캐스팅(Broadcasting) 방식이라 버스에 흐르는 모든 메시지가 모든 ECU로 들어옵니다.

CPU가 모든 메시지를 수신 인터럽트로 처리하면 과부하가 걸리므로, 하드웨어 필터(Acceptance Filter)가 나에게 상관없는 Message ID는 들어오자마자 튕겨내고 필요한 것만 RX FIFO로 넣어줍니다.

STM32 bxCAN은 두 가지 필터 모드를 제공합니다.

### ① Identifier Mask 모드 (마스크 모드) — "범위 지정 수신"

- 구성: Filter ID 레지스터 + Filter Mask 레지스터
- 원리: Mask 비트가 1인 자리는 Filter ID와 완벽히 일치해야 하고, Mask 비트가 0인 자리는 Don't Care (0이든 1이든 통과) 처리합니다.
```plain text
[ 예시 ]
Filter ID   : 0x120  (0001 0010 0000)
Filter Mask : 0x7F0  (0111 1111 0000)  ← 상위 8비트만 검사하겠다는 의미!

수신된 ID   : 0x123  (0001 0010 0011)  ➔ 상위 8비트 일치 ⭕ (수신 통과)
수신된 ID   : 0x12F  (0001 0010 1111)  ➔ 상위 8비트 일치 ⭕ (수신 통과)
수신된 ID   : 0x130  (0001 0011 0000)  ➔ 상위 8비트 불일치 ❌ (차단)

💡 사용처: 0x120 ~ 0x12F 처럼 특정 그룹의 ID 전체를 묶어서 수신할 때 사용
```

### ② Identifier List 모드 (리스트 모드) — "화이트리스트 지정 수신"

- 구성: Filter ID 1 레지스터 + Filter ID 2 레지스터
- 원리: Mask 개념 없이, 레지스터에 등록된 ID와 100% 토씨 하나 안 틀리고 일치하는 메시지만 통과시킵니다.
```plain text
[ 예시 ]
Filter ID 1 : 0x100
Filter ID 2 : 0x200

수신된 ID   : 0x100  ➔ 일치 ⭕ (수신 통과)
수신된 ID   : 0x200  ➔ 일치 ⭕ (수신 통과)
수신된 ID   : 0x101  ➔ 불일치 ❌ (차단)

💡 사용처: 받아야 할 ID가 정확히 몇 개 지정되어 있을 때 사용
```

## 3. ⚙️ STM32 bxCAN 핵심 레지스터 설정 흐름

STM32(F1, F4 시리즈)의 기본 CAN IP인 bxCAN을 설정할 때 건드리는 핵심 레지스터들입니다.

### ① CAN_MCR (Master Control Register) — 초기화 및 제어

- INRQ (Initialization Request): 1로 설정하여 CAN 초기화 모드로 진입 (통신 속도, 필터 설정 전 필수).
- NART (No Automatic Retransmission): 0 = 에러 시 자동 재전송, 1 = 재전송 안 함.
- TXFP (Transmit FIFO Priority): 송신 우선순위를 ID 기준(0)으로 할지, 요청 순서(1)로 할지 결정.
### ② CAN_MSR (Master Status Register) — 상태 확인

- INAK (Initialization Acknowledge): 초기화 모드로 정상 진입했는지 확인 (INAK == 1일 때 설정 진행).
### ③ CAN_BTR (Bit Timing Register) — 통신 속도(Baud Rate) 설정

CAN의 통신 속도는 PCLK1 클럭을 분주하여 설정합니다.

BaudRate = \frac{f_{PCLK1}}{\text{BRP} \times (1 + \text{TS1} + \text{TS2})}

- BRP[9:0] (Baud Rate Prescaler): 클럭 분주비 설정.
- TS1[3:0], TS2[2:0] (Time Segment 1, 2): 샘플링 포인트(Sample Point) 위치 결정.
- SILM / LBKM: Test 모드 설정 (Silent 모드, Loopback 모드).
### ④ 필터 관련 레지스터 설정 순서 (CAN_FMR 등)

1. CAN_FMR->FINIT = 1 : 필터 초기화 모드 진입.
1. CAN_FM1R : Bank별로 Mask 모드(0) 또는 List 모드(1) 선택.
1. CAN_FS1R : 16-bit Scale(0) 또는 32-bit Scale(1) 선택.
1. CAN_FFA1R : 필터통과 데이터를 FIFO 0(0)에 보낼지, FIFO 1(1)에 보낼지 지정.
1. CAN_FiRx (Filter Register) : 실제 Match ID 및 Mask 값 대입.
1. CAN_FA1R : 해당 Filter Bank 활성화(1).
1. CAN_FMR->FINIT = 0 : 필터 설정 완료 및 탈출.
### 💡 면접용 핵심 요약
