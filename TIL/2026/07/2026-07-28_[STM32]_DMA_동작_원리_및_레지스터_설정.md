# 🚀 DMA (Direct Memory Access) 총정리

<a id="notion-3ab1d46c18fc800ea37eed31fdbf6fdc"></a>

## 1\. 📌 DMA란 무엇인가? (개념 및 존재 이유)

DMA는 **CPU의 개입 없이** 주변장치(Peripheral)와 메모리(SRAM), 또는 메모리와 메모리 간에 **데이터를 고속으로 직접 전송하는 전용 하드웨어 제어기**입니다.

<a id="notion-3ab1d46c18fc80a585c2e36eb7714b0a"></a>

### 💡 기존 방식 vs DMA 방식 비교

```text
[ 기존 방식 (CPU Polling / Interrupt) ]
  ADC/UART ──(데이터 발생)──▶ CPU ──(읽고 쓰기)──▶ SRAM
  * 문제점: 데이터가 들어올 때마다 CPU가 일을 멈추고 복사 작업에 매달려야 함.

[ DMA 방식 ]
  ADC/UART ──────────(DMA Controller)──────────▶ SRAM
                       (CPU는 딴일 중!)
  * 장점: CPU는 데이터 전송 신경 안 쓰고 연산/제어 알고리즘만 집중 수행 가능!
```

<a id="notion-3ab1d46c18fc80fb862cf7695a79ca7b"></a>

## 2\. ⚙️ DMA 전송의 3가지 유형

|  |  |  |
| --- | --- | --- |
| **전송 유형 (Mode)** | **설명** | **주요 사용 예시** |
| **Peripheral to Memory** | 주변장치 수신 데이터 $\rightarrow$ 메모리 | ADC 연속 변환 수집, UART Rx(수신) |
| **Memory to Peripheral** | 메모리 데이터 $\rightarrow$ 주변장치 출력 | UART Tx(대량 송신), DAC 음원/파형 출력, SPI 디스플레이 전송 |
| **Memory to Memory** | 메모리 특정 영역 $\rightarrow$ 다른 메모리 영역 | 큰 배열/버퍼 복사 (`memcpy` 대체) |

<a id="notion-3ab1d46c18fc806f8695f1b69e24694e"></a>

## 3\. 🎯 DMA를 쓰면 '무조건 좋은' 3가지 상황

<a id="notion-3ab1d46c18fc80188bd4f608bf856b97"></a>

### ① \[최고의 궁합\] 다채널 ADC 스캐닝 (Multi-Channel ADC) 🔥

- **이유:** STM32의 ADC 일반 그룹(Regular Group)은 <strong>데이터 레지스터(</strong><strong>`ADC_DR`</strong><strong>)가 단 1개뿐</strong>입니다.
- **문제:** Ch0, Ch1, Ch2를 순차적으로 스캔할 때 CPU가 제때 읽어가지 않으면 **다음 채널 데이터가 이전 채널 데이터를 덮어써서(Overrun) 손실**됩니다.
- **DMA 해결:** ADC 변환 완료(`EOC`) 신호가 뜰 때마다 DMA가 <strong>배열(</strong><strong>`uint16_t adc_buf[3]`</strong><strong>)에 알아서 0번, 1번, 2번 순서대로 착착 복사</strong>해 줍니다.

<a id="notion-3ab1d46c18fc803e8dbcffe41a71a39b"></a>

### ② 고속 시리얼 통신 (UART / SPI / I2C 대량 전송)

- **이유:** UART로 $1000\text{ Byte}$ 텍스트를 출력하거나 SPI로 TFT-LCD 화면에 $320 \times 240$ 이미지를 그릴 때, 1 바이트씩 인터럽트로 보내면 **초당 수만 번의 인터럽트**가 발생해 CPU가 마비됩니다.
- **DMA 해결:** "메모리 $A$번지부터 $1000\text{ Byte}$를 SPI로 쏴라\!" 하고 DMA를 켜두면, **CPU는 0.001초도 낭비하지 않고 다음 코드를 실행**합니다.

<a id="notion-3ab1d46c18fc804bb143d0ea579f9afa"></a>

### ③ 실시간 신호 처리 및 센서 모니터링 (Circular Mode)

- DMA의 순환 모드(Circular Mode)를 켜면, 지정한 메모리 버퍼가 다 찼을 때 **다시 처음 0번지부터 덮어쓰며 무한 반복**합니다.
- 백그라운드에서 실시간으로 항상 최신 센서 값이 메모리에 자동 갱신되므로, CPU는 필요할 때 버퍼의 값만 쏙 가져다 쓰면 됩니다.

<a id="notion-3ab1d46c18fc802a9fe6ccb040bd848e"></a>

## 🛠️ DMA 관련 핵심 키워드 (시험 &amp; 면접 단골)

1. **Circular Mode (순환 모드):**

   - 설정한 데이터 개수(CNDTR)만큼 전송이 끝나면 **자동으로 주소와 카운터를 리셋하여 무한 반복 전송**하는 모드.
2. **Increment Address (주소 증가 옵션):**

   - **Memory Address Increment (MINC):** 데이터가 들어올 때마다 SRAM 주소를 1씩 증가시킴 (배열 저장용).
   - **Peripheral Address Increment (PINC):** ADC나 UART 레지스터 주소는 고정이므로 보통 Disable 고정.
3. **Half Transfer (HT) / Transfer Complete (TC) Interrupt:**

   - DMA 전송이 절반 완료되었을 때(`HT`) 또는 전체 완료되었을 때(`TC`) 인터럽트를 발생시켜 CPU에게 알려주는 기능.

💡 **요약:**

프로젝트에서 <strong>"가변저항 여러 개를 실시간으로 읽어야 하거나"</strong>, **"UART/SPI 통신으로 긴 데이터를 끊김 없이 주고받아야 할 때"** DMA를 적용하시면 **CPU 성능 점수와 코드 완성도**에서 아주 높은 평가를 받을 수 있습니

# 🚀 \[DMA 요약 및 완벽 해설\]

<a id="notion-3ab1d46c18fc8069a551e18c46f9db6f"></a>

## 1\. 📌 DMA 개념 및 핵심 동작 메커니즘

<a id="notion-3ab1d46c18fc80afba46fd8e8cc7be06"></a>

### ① 존재 이유 &amp; Cycle Steal (버스 훔치기)

- **원리:** CPU가 내부 연산/캐시 작업을 처리하느라 외부 메모리 버스(Bus)를 쓰지 않는 **찰나의 타이밍**을 노려 DMA가 버스 제어권을 빌려 데이터를 복사합니다.
- **4단계 버스 제어 순서 (Cycle Stealing):**

  1. **BR (Bus Request):** DMA가 CPU에게 버스 제어권을 달라고 요청.
  2. **BA (Bus Ack):** CPU가 내부 타이밍에 맞춰 버스를 DMA에 승인/양보.
  3. **Transfer:** DMA가 $1\,\text{Unit}$ (1바이트/2바이트/4바이트) 데이터 복사 수행.
  4. **제어권 반납:** $1\,\text{Unit}$ 이동 후 버스 제어권을 즉시 CPU에게 다시 반납.
  5. 정해진 전송 횟수(`NDTR`)를 모두 채울 때까지 위 1\~4 과정을 무한 반복.

<a id="notion-3ab1d46c18fc8040b3dac65d20965d0e"></a>

## 2\. ⚙️ STM32F411 DMA 하드웨어 구조

- **2개의 DMA 컨트롤러 (DMA1, DMA2):**

  - 각 DMA 컨트롤러당 **8개의 Stream**을 가집니다.
  - 각 Stream당 **8개의 Channel (Ch0 \~ Ch7)** 중 하나를 선택해 주변장치(UART, SPI, ADC 등)와 연결합니다.
- **⚠️ M2M (Memory-to-Memory)의 결정적 제약:**

  - **Memory-to-Memory(M2M) 모드는 오직 DMA2에서만 지원**됩니다 (DMA1은 불가\!).
  - M2M 설정 시 채널(`CHSEL`) 값은 의미가 없습니다.
  - **STM32F411 특성:** M2M 모드를 사용할 경우 반드시 FIFO 모드를 활성화(`DMDIS = 1`)해야 동작합니다.

<a id="notion-3ab1d46c18fc80828e44f5ce3d38ee70"></a>

## 3\. 🛠️ DMA 레지스터 주요 설정값 정리

|  |  |  |
| --- | --- | --- |
| **레지스터 명칭** | **역할** | **주요 설정 비트/필드** |
| **`DMAx_Streamn->CR`** | 스트림 기본 동작 제어 | • `DIR[1:0]` : 전송 방향 (P2M, M2P, M2M)  <br><br>• `CIRC` : 순환 모드 (M2M은 미지원)  <br><br>• `MINC` / `PINC` : 메모리/주변장치 주소 증가 여부  <br><br>• `MSIZE` / `PSIZE` : 1 Unit 데이터 크기 (8/16/32비트)  <br><br>• `CHSEL[2:0]` : H/W 트리거 채널 선택 (0\~7, M2M 의미 X)  <br><br>• `TCIE` / `HTIE` : 전송 완료 / 절반 완료 인터럽트 허용<br><br>• `MBURST` / `PBURST` : 연속된 데이터 (4개, 8개, 16개 Unit) 전송 |
| **`DMAx_Streamn->NDTR`** | 전송할 데이터 개수 | • $1 \sim 65,535$ 개 설정 가능 (전송 시 1씩 자동 감소) |
| **`DMAx_Streamn->PAR`** | Peripheral (주변장치) 주소 | • M2M일 경우 **Source(원본) 주소**<br> |
| **`DMAx_Streamn->M0AR`** | Memory (메모리) 주소 | • M2M일 경우 **Destination(목적지) 주소**<br> |
| **`DMAx_Streamn->FCR`** | FIFO 및 Direct 모드 제어 | • `DMDIS` : 0(Direct), 1(FIFO 사용 - M2M 필수) |
| **`DMAx->LIFCR / HIFCR`** | 인터럽트 플래그 클리어 | • `CTCIFx` (전송 완료), `CTEIFx` (에러) 등에 `1`을 써서 클리어 |

<a id="notion-3ab1d46c18fc808dab31f2d799bbf22f"></a>

## 4\. 💡 UART2 TX DMA 전송 예제

<a id="notion-3ab1d46c18fc80c9a3f6e72743d17f2a"></a>

### ① 초기화 및 설정 (`dma.c` \- `DMA1_Stream6_USART2_TX_Start`)

1. `RCC->AHB1ENR` Bit 21 활성화 $\rightarrow$ **DMA1 클럭 ON**.
2. `PAR = &USART2->DR` $\rightarrow$ 목적지 주변장치를 **UART2 Data Register**로 지정.
3. `M0AR = src_addr` $\rightarrow$ 원본 데이터를 보낼 **문자열 메모리 주소** 지정.
4. `NDTR = num` $\rightarrow$ **전송할 문자열 길이** 설정.
5. `DIR = 01` (Memory-to-Peripheral), `MINC = 1` (메모리 주소 자동 증가).
6. `USART2->CR3` Bit 7 (`DMAT`) 비트 Set $\rightarrow$ **UART2 하드웨어에게 DMA 전송 요청(Trigger) 허용**.
7. `DMA1_Stream6->CR` Bit 0 (`EN = 1`) $\rightarrow$ **DMA 전송 개시\!**

<a id="notion-3ab1d46c18fc8023b939cb3bb624b676"></a>

### ② 동작 중 (`main.c` &amp; `exception.c`)

- CPU는 `printf`나 `for`문으로 갇혀있지 않고 <strong>다른 실시간 업무(</strong><strong>`if(TIM4_Expired)`</strong><strong>)를 100% 속도로 계속 처리</strong>합니다.
- DMA가 알아서 UART2 DR 레지스터로 1바이트씩 쏩니다.
- 전송이 완료되면 `DMA1_Stream6_IRQHandler()` 인터럽트가 실행되어 `DMA1_STREAM6_DONE = 1` 플래그를 세우고 다음 문장을 준비합니다.

<a id="notion-3ab1d46c18fc80ff908fc86b99240fa0"></a>

## 🔍 실무에서 알아야 할 중요한 내용

<a id="notion-3ab1d46c18fc80bbb165f2b911a1d7d5"></a>

### 1\. ⚠️ UART 송신 시 `TXE` vs `TC` 플래그의 명확한 차이

- **`TXE`** <strong>(Transmit Data Register Empty):</strong> 송신 버퍼 레지스터가 비어서 "다음 글자를 써도 됨"을 의미 (아직 핀으로 신호가 나가는 중일 수 있음).
- **`TC`** <strong>(Transmission Complete):</strong> 쉬프트 레지스터까지 완전히 비어서 "마지막 1비트까지 안테나/핀으로 다 나감"을 의미.
- **DMA 실무 적용 시:** DMA 전송 직전에 `Uart2_Wait_for_TX_Complete()`를 불러주는 이유는, **이전 데이터가 핀 밖으로 완전히 다 나가기도 전에 DMA가 새로 버퍼를 건드리는 충돌을 막기 위함**입니다.

<a id="notion-3ab1d46c18fc803f9ba4c15ab6dd0419"></a>

### 2\. 🔄 Circular Mode (순환 모드) 동작 원리

- `CR` 레지스터의 `CIRC` 비트를 1로 설정하면, `NDTR` 카운터가 `0`이 되는 순간 자동으로 처음에 설정했던 원본 `NDTR` 값과 메모리 주소로 복구(Auto-Reload)됩니다.
- **ADC 다채널 연속 스캔**이나 **UART Ring Buffer 수신** 시 `while`문 없이 무한히 백그라운드 데이터 수집을 가능하게 해주는 핵심 모드입니다.

<a id="notion-3ab1d46c18fc806f8a17c4fe6be52197"></a>

### 3\. 🚨 캐시(Cache)와 메모리 일관성 (Cortex-M4/M7 주의사항)

- CPU가 SRAM의 데이터를 수정했을 때 메모리 캐시(D-Cache)에만 남아있고 실제 SRAM에 아직 반영되지 않았을 경우, **DMA가 옛날 데이터를 읽어서 전송하는 오류**가 생길 수 있습니다.
- 이럴 경우 코드상에서 `SCB_CleanDCache()` 등의 함수로 **캐시 flush 처리**를 해주어야 함을 알고 계시면 좋습니다.

```c
void DMA2_Stream0_M2M_Start(void *src_addr, void *dst_addr, int num)
{
	// DMA2 Clock On
	Macro_Set_Bit(RCC->AHB1ENR, 22);

	// CHSEL [0]: 채널 선택 0
	// MSIZE [16b]: Mem측 1 Unit Size (16b)
	// PSIZE [16b]: Peri측 1 Unit Size (16b)
	// MINC [1]: Mem 주소 증가 모드
	// PINC [1]: Peri 주소 증가 모드
	// DIR [2]: M2M
	// EN [0]: DMA Disable
	DMA2_Stream0->CR = (0x0 << 25) | (0x2 << 13) | (0x2 << 11) | (0x1 << 10) | (0x1 << 9) | (0x2 << 6) | (0x0 << 0);
	// DMDIS [Disable]: Direct Mode Disable (M2M인 경우 FIFO를 거쳐야 함)
	// FTH [4/4]: FIFO Threshold Selection (경계값만큼 쌓이면 방출)
	DMA2_Stream0->FCR = (0x1 << 2) | (0x3 << 0);
	// M2M인 경우 Source가 Peri측이 됨
	DMA2_Stream0->PAR = (unsigned int)src_addr;
	DMA2_Stream0->M0AR = (unsigned int)dst_addr;
	DMA2_Stream0->NDTR = num;

	DMA2->LIFCR = 0x3F << 0;			// Pending Clear
	Macro_Set_Bit(DMA2_Stream0->CR, 4); // TCIE
	NVIC_ClearPendingIRQ(DMA2_Stream0_IRQn);
	NVIC_EnableIRQ(DMA2_Stream0_IRQn);

	Macro_Set_Bit(DMA2_Stream0->CR, 0); // DMA Enable
}

void DMA1_Stream6_USART2_TX_Start(void *src_addr, int num)
{
	// DMA1 Clock On (AHB1 버스의 Bit 21 활성화)
	Macro_Set_Bit(RCC->AHB1ENR, 21);

	// CHSEL [4]   : 채널 선택 4 (USART2_TX 전용 채널 지정)
	// MSIZE [8b]  : Mem측 1 Unit Size (8bit / 1 Byte)
	// PSIZE [8b]  : Peri측 1 Unit Size (8bit / 1 Byte)
	// MINC [1]    : Mem 주소 증가 모드 (문자열 배열 순회)
	// PINC [0]    : Peri 주소 고정 모드 (&USART2->DR 레지스터 주소 고정)
	// DIR [1]     : Memory-to-Peripheral (M2P: RAM -> USART2 TX)
	// EN [0]      : DMA Disable (설정 중 안전을 위해 비활성화)
	DMA1_Stream6->CR = (0x4 << 25) | (0x0 << 13) | (0x0 << 11) | (0x1 << 10) | (0x0 << 9) | (0x1 << 6) | (0x0 << 0);

	// DMDIS [Enable] : Direct Mode Enable (0 = FIFO 사용 안 함, M2P 직송 모드)
	DMA1_Stream6->FCR = 0;

	// PAR  : Destination(목적지) 주변장치 주소 (&USART2->DR Data Register)
	// M0AR : Source(출발지) 메모리 주소 (전송할 문자열 버퍼 주소)
	// NDTR : 전송할 데이터 개수 (문자열 길이/바이트 수)
	DMA1_Stream6->PAR = (unsigned int)&USART2->DR;
	DMA1_Stream6->M0AR = (unsigned int)src_addr;
	DMA1_Stream6->NDTR = num;

	// Stream 6번 찌꺼기 상태/인터럽트 플래그 초기화 (HIFCR의 bit 16~21 범위 clear)
	DMA1->HIFCR = 0x3F << 16; // (참고: Stream 6번용 offset은 bit 16부터 시작합니다)

	// TCIE [1] : Transfer Complete Interrupt Enable (전송 완료 인터럽트 허용)
	Macro_Set_Bit(DMA1_Stream6->CR, 4);

	// NVIC 설정 (17번: DMA1_Stream6 전용 IRQ)
	NVIC_ClearPendingIRQ(DMA1_Stream6_IRQn);
	NVIC_EnableIRQ(DMA1_Stream6_IRQn);

	// DMA Enable (USART2 TX DMA 전송 개시!)
	Macro_Set_Bit(DMA1_Stream6->CR, 0);
}
```
