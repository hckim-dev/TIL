# 🔌 I2C (Inter-Integrated Circuit) 통신 총정리

<a id="notion-3aa1d46c18fc80d8bdebc81b42c47f20"></a>

## 1\. I2C 개념 및 기본 특징

I2C는 Philips(현 NXP)사에서 개발한 **동기식(Synchronous) 시리얼 통신 규격**으로, 단 **2개의 라인**만으로 1:N 또는 M:N 기기 간 통신을 수행합니다.

|  |  |  |
| --- | --- | --- |
| **구 분** | **제 어 신 호** | **용 도** |
| **SCL** (Serial Clock) | 마스터(Master)가 생성 | 통신 클럭 신호 전송 (동기화) |
| **SDA** (Serial Data) | 마스터 및 슬레이브 양방향 | 실제 데이터(Data) 송수신 |

- **Multi-Master / Multi-Slave 지원:** 고유의 7비트(또는 10비트) 슬레이브 주소(Slave Address)를 사용해 원하는 장치를 지정합니다.
- **통신 속도:** Standard Mode ($100\,\text{kHz}$), Fast Mode ($400\,\text{kHz}$), Fast Mode Plus ($1\,\text{MHz}$) 등.

<a id="notion-3aa1d46c18fc804f8c4bc2f58ec16c06"></a>

## 2\. ⚡ 왜 반드시 Open-Drain (오픈 드레인)을 써야 할까?

I2C 버스의 SCL과 SDA 라인은 **반드시 Open-Drain(또는 Open-Collector) 구조**로 핀을 설정하고, 라인마다 **외부 Pull-Up(풀업) 저항**을 달아주어야 합니다. 이에는 2가지 결정적인 이유가 있습니다.

```text
                   [ VCC (3.3V / 5V) ]
                            │
               ┌────────────┴────────────┐
             [R_PU] (풀업 저항)        [R_PU] (풀업 저항)
               │                         │
  SDA Line ────┼─────────────────────────┼───────
               │                         │
  SCL Line ────┼─────────────────────────┼───────
               │                         │
        ┌──────┴──────┐           ┌──────┴───────┐
        │ MCU (Master)│           │ Sensor(Slave)│
        └─────────────┘           └──────────────┘
```

<a id="notion-3aa1d46c18fc803d877fd823ae88dbc2"></a>

### ① 버스 쇼트(Short Circuit) 및 칩 파손 방지 (Bus Contention Prevention)

- 만약 핀을 일반적인 **Push-Pull**로 설정했다고 가정해 봅시다.

  - **Master 핀:** High ($3.3\,\text{V}$) 출력 (상단 FET ON)
  - **Slave 핀:** Low ($0\,\text{V}$) 출력 (하단 FET ON)
- 이때 두 장치가 하나의 선(SDA)에서 동시에 신호를 내보내면 $3.3\,\text{V}$와 $0\,\text{V}$가 직접 연결되어 과전류가 흐르고 칩이 파손(Short)됩니다.
- **Open-Drain 사용 시:**

  - 핀은 <strong>Low(</strong><strong>$0\,\text{V}$</strong><strong>) 출력</strong> 또는 **High-Z(플로팅)** 상태만 만듭니다.
  - 아무도 신호를 주지 않을 땐 풀업 저항에 의해 High($3.3\,\text{V}$)가 되고, 누군가 라인을 끌어내리면 Low($0\,\text{V}$)가 되므로 **절대 충돌이나 쇼트가 나지 않습니다.**

<a id="notion-3aa1d46c18fc80069791f54ff157cf17"></a>

### ② Wired-AND (와이어드 AND) 논리 구현

- Open-Drain 선로에서는 라인에 연결된 수많은 장치 중 <strong>단 하나라도 Low(</strong><strong>$0\,\text{V}$</strong><strong>)를 출력하면 전체 선로가 Low</strong>가 됩니다.
- 이 특징을 활용하여 아래와 같은 I2C 필수 기능을 하드웨어적으로 구현합니다:

  - **ACK / NACK 응답:** 마스터가 데이터를 보낸 후 라인을 release(High-Z)하면, 슬레이브가 SDA를 Low로 잡아당겨 ACK 신호를 보냄.
  - **Clock Stretching (클럭 스트레칭):** 슬레이브가 처리 속도가 느릴 때, SCL 선을 강제로 Low로 잡아두어 마스터의 클럭을 잠시 멈춤.
  - **Multi-Master 중재 (Arbitration):** 여러 마스터가 동시에 송신할 때, 자신이 High를 냈는데 선로가 Low이면 전송을 포기하고 빠짐.

<a id="notion-3aa1d46c18fc807ca71af5bb9f91fd75"></a>

## 3\. 📡 I2C 통신 프로토콜 흐름

I2C 신호는 SCL이 High일 때 SDA의 상태 변화에 따라 조건이 결정됩니다.

```text
SCL:  ───┐       ┌─── ... ───┐       ┌───
         └───────┘           └───────┘
SDA:  ──┐                 ┌── ... ───┐
        └─────────────────┘          └────
        ▲ Start Condition            ▲ Stop Condition
```

- **START Condition:** SCL이 **High**인 상태에서 SDA가 <strong>High</strong> **$\rightarrow$** <strong>Low</strong>로 바뀔 때
- **STOP Condition:** SCL이 **High**인 상태에서 SDA가 <strong>Low</strong> **$\rightarrow$** <strong>High</strong>로 바뀔 때
- **Data Valid (데이터 유효 구간):** SCL이 **Low**일 때만 SDA 데이터를 변경하고, SCL이 **High**일 때는 SDA 데이터를 유지(Stable)해야 함.

<a id="notion-3aa1d46c18fc80d7a70beb980178d6b7"></a>

### 🔄 1바이트 전송 프레임 구조 (총 9비트)

1. <strong>Master</strong> **$\rightarrow$** <strong>Slave (8비트):</strong> 슬레이브 주소 (7비트) + Read/Write 비트 (1비트: `0`=Write, `1`=Read)
2. <strong>Slave</strong> **$\rightarrow$** <strong>Master (1비트):</strong> **ACK/NACK**

   - <strong>ACK (</strong><strong>`0`</strong><strong>):</strong> 슬레이브가 SDA 라인을 GND로 끌어내림 (성공)
   - <strong>NACK (</strong><strong>`1`</strong><strong>):</strong> 아무도 라인을 안 잡아서 High 상태로 남음 (실패/끝)

<a id="notion-3aa1d46c18fc8016b650fea499c3711f"></a>

## 4\. 📝 요약

> **Q. I2C에서 Open-Drain 모드를 사용하는 핵심 이유 2가지는?**
>
> 1. Push-Pull 사용 시 발생할 수 있는 마스터/슬레이브 간 **전원 충돌(Short Circuit)을 방지**하기 위해.
> 2. **Wired-AND** 특성을 이용하여 **ACK/NACK 응답, Clock Stretching, Multi-Master 중재 기능**을 구현하기 위해.

<a id="notion-3aa1d46c18fc802e828ef22dcd6aafe6"></a>

# ⚡ SPI (Serial Peripheral Interface) 통신 총정리

<a id="notion-3aa1d46c18fc80d18e96f45505b7f9dc"></a>

## 1\. SPI 개념 및 기본 특징

SPI는 Motorola사에서 제안한 **고속 동기식(Synchronous) 전이중(Full-Duplex) 시리얼 통신 규격**입니다. I2C보다 훨씬 빠른 속도가 필요할 때(SD카드, TFT-LCD 디스플레이, 고속 Flash 메모리 등) 주로 사용됩니다.

|  |  |  |  |
| --- | --- | --- | --- |
| **제 어 신 호** | **핀 명 칭** | **명 칭 풀 이** | **역 할** |
| **SCLK** / **SCK** | Serial Clock | 시리얼 클럭 | 마스터가 출력하는 통신 클럭 |
| **MOSI** | Master Out Slave In | 마스터 출력 / 슬레이브 입력 | 마스터 $\rightarrow$ 슬레이브 데이터 전송 |
| **MISO** | Master In Slave Out | 마스터 입력 / 슬레이브 출력 | 슬레이브 $\rightarrow$ 마스터 데이터 전송 |
| **CS** / **NSS** / **SS** | Chip Select / Slave Select | 칩 선택 (Enable) | 통신할 대상 슬레이브를 지정 (Active Low) |

- **전이중(Full-Duplex) 통신:** MOSI와 MISO 라인이 분리되어 있어 **송신과 수신을 동시에** 진행합니다.
- **고속 통신:** 별도의 인코딩/디코딩이나 주소 프레임 없이 Shift Register로 직접 비트를 주고받으므로 **수 MHz \~ 수십 MHz** 대역의 매우 높은 속도를 지원합니다.
- **Master-Slave 구조:** 반드시 **1개의 Master**가 클럭(SCLK)과 CS 신호를 주도합니다.

<a id="notion-3aa1d46c18fc8016aec4f7fa9403442d"></a>

## 2\. 🔌 I2C vs SPI 비교

|  |  |  |
| --- | --- | --- |
| **구 분** | **I2C (Inter-Integrated Circuit)** | **SPI (Serial Peripheral Interface)** |
| **핀 개수** | **2개** (SDA, SCL) | **4개** (MOSI, MISO, SCLK, CS) |
| **출력 방식** | **Open-Drain** (외부 Pull-Up 필수) | **Push-Pull** (전용 라인, 빠름) |
| **통신 방식** | 반이중 (Half-Duplex) | **전이중 (Full-Duplex)** |
| **슬레이브 선택** | 7비트/10비트 **주소(Address)** 전송 | **CS (Chip Select) 핀**을 Low로 내림 |
| **통신 속도** | 상대적으로 느림 ($100\,\text{kHz} \sim 400\,\text{kHz}$) | <strong>매우 빠름 (</strong><strong>$10\,\text{MHz} \sim 80\,\text{MHz}+$</strong> <strong>)</strong> |
| **장/단점** | 핀 수가 적으나 프로토콜 오버헤드 있음 | 속도가 매우 빠르나 핀 소비가 많음 |

<a id="notion-3aa1d46c18fc801a83cdd480599094a3"></a>

## 3\. ⚙️ SPI 동작 모드 (CPOL &amp; CPHA)

SPI는 클럭의 극성(CPOL)과 위상(CPHA)에 따라 총 4가지 모드(Mode 0\~3)로 동작합니다. 마스터와 슬레이브의 모드가 서로 일치해야 데이터가 깨지지 않습니다.

```text
CPOL (Clock Polarity): 평상시(Idle) 클럭 라인의 전압 상태
  - 0: 평상시 Low (0V)
  - 1: 평상시 High (3.3V)

CPHA (Clock Phase): 데이터를 캡처(Sample)하는 엣지 시점
  - 0: 첫 번째 클럭 엣지(Rising or Falling)에서 Read (Sample)
  - 1: 두 번째 클럭 엣지(Rising or Falling)에서 Read (Sample)

CPOL: 클럭의 기본 바탕 평상시 전압(0V냐 3.3V냐)을 결정.
CPHA: 클럭이 칠 때 "첫 엣지에서 읽을 거냐(0), 두 번째 엣지에서 읽을 거냐(1)"를 결정.
```

|  |  |  |  |
| --- | --- | --- | --- |
| **SPI Mode** | **CPOL** | **CPHA** | **데이터 샘플링 시점** |
| **Mode 0** (가장 흔함) | `0` | `0` | 클럭의 **첫 번째 상승 엣지 (Rising Edge)** |
| **Mode 1** | `0` | `1` | 클럭의 **두 번째 하강 엣지 (Falling Edge)** |
| **Mode 2** | `1` | `0` | 클럭의 **첫 번째 하강 엣지 (Falling Edge)** |
| **Mode 3** | `1` | `1` | 클럭의 **두 번째 상승 엣지 (Rising Edge)** |

<a id="notion-3aa1d46c18fc806a9b1ddc11ce8fcf49"></a>

## 4\. 🔄 Shift Register 기반 데이터 교환 원리

SPI 내부 구조는 마스터와 슬레이브의 **Shift Register가 하나의 거대한 원형(Ring) 구조**로 연결된 형태입니다.

```text
       [ Master Shift Register ]
         ┌───┬───┬───┬───┬───┐
      ┌─>│ 7 │ 6 │ 5 │...│ 0 │─┐
      │  └───┴───┴───┴───┴───┘ │
   MISO                        MOSI
      │  ┌───┬───┬───┬───┬───┐ │
      └─ │ 7 │ 6 │ 5 │...│ 0 │<┘
         └───┴───┴───┴───┴───┘
        [ Slave Shift Register ]
```

- 마스터가 SCLK 펄스를 1번 발생시킬 때마다 비트가 1칸씩 이동합니다.
- **8번의 클럭 펄스**가 지나면, **마스터의 데이터는 슬레이브로 들어가고, 슬레이브의 데이터는 마스터로 들어옵니다.**
- 💡 **특징:** 데이터를 읽기(Read)만 하려고 할 때도 마스터는 Dummy Byte(예: `0xFF`)를 송신(Write)하여 클럭을 발생시켜야 데이터를 받아올 수 있습니다.

<a id="notion-3aa1d46c18fc80faaf5be7428a616a34"></a>

## 5\. 📝 요약

> **Q. SPI에서 데이터를 받기만(Read) 하고 싶은데 왜 Dummy Data를 송신(Write)해야 하나요?**
>
> - **A:** SPI는 마스터가 SCLK(클럭)을 생성해야만 데이터 이동이 일어나는 구조입니다. 따라서 마스터가 의미 없는 쓰기 동작(Dummy Data 전송)을 수행해 **SCLK 펄스를 발생시켜 주어야만 슬레이브의 데이터가 MISO 라인을 타고 들어오기 때문**입니다.

```c
#define SC16IS752_IODIR 0x0AU // IO 방향 레지스터 (0: Output, 1: Input)
#define SC16IS752_IOSTATE 0x0BU // IO 출력 상태 레지스터

#define SPI1_CS_HIGH() (Macro_Set_Bit(GPIOA->ODR, 8U))
#define SPI1_CS_LOW() (Macro_Clear_Bit(GPIOA->ODR, 8U))

void SPI1_Init(unsigned int div)
{
	volatile int i;

	int n = (__builtin_ctz(div) & 0x7) - 1;
	if (n < 0)
		n = 0;

	Macro_Set_Bit(RCC->AHB1ENR, 0U);  // GPIOA
	Macro_Set_Bit(RCC->AHB1ENR, 1U);  // GPIOB
	Macro_Set_Bit(RCC->APB2ENR, 12U); // SPI1

	Macro_Clear_Bit(RCC->APB2RSTR, 12U);
	Macro_Set_Bit(RCC->APB2RSTR, 12U);
	for (i = 0; i < 1000; i++)
		;
	Macro_Clear_Bit(RCC->APB2RSTR, 12U);

	// PA8(nCS) => Output Push-Pull
	Macro_Write_Block(GPIOA->MODER, 0x3, 0x1, 16U);
	Macro_Clear_Bit(GPIOA->OTYPER, 8U);
	SPI1_CS_HIGH();

	// PB3(SCK), PB4(MISO), PB5(MOSI) => AF05
	Macro_Write_Block(GPIOB->MODER, 0x3F, 0x2A, 6U);
	Macro_Write_Block(GPIOB->AFR[0], 0xFFF, 0x555, 12U);
	Macro_Write_Block(GPIOB->OTYPER, 0x7, 0x0, 3U);
	Macro_Write_Block(GPIOB->OSPEEDR, 0x3F, 0x2A, 6U);

	SPI1->CR2 = (0U << 4U) | (1U << 2U);

	// SSM(Bit 9)=1, SSI(Bit 8)=1 추가로 Master mode 다운 현상 방지
	SPI1->CR1 = (1U << 11U) | (1U << 9U) | (1U << 8U) | ((unsigned int)n << 3U) | (1U << 2U);
	Macro_Set_Bit(SPI1->CR1, 6U); // SPE
}

void SPI1_Write_Reg(unsigned int addr, unsigned int data)
{
	SPI1_CS_HIGH();
	SPI1_CS_LOW();

	SPI1->DR = (0U << 15U) | ((addr & 0x0FU) << 11U) | (data & 0xFFU);
	while (Macro_Check_Bit_Clear(SPI1->SR, 1U))
		; // TXE
	while (Macro_Check_Bit_Set(SPI1->SR, 7U))
		; // BSY

	SPI1_CS_HIGH();
}

void SPI1_Config_GPIO(unsigned int config)
{
	// SC16IS752 칩은 0xFF 가 8개 핀 전체 Output 모드입니다.
	SPI1_Write_Reg(SC16IS752_IODIR, config);
}

void SPI1_Write_GPIO(unsigned int data)
{
	SPI1_Write_Reg(SC16IS752_IOSTATE, data);
}
```
